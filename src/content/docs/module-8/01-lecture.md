## 1. Що таке React Native

**React Native** — це фреймворк із відкритим кодом від Meta для створення мобільних застосунків під Android та iOS (а також, з додатковими пакетами, під Windows, macOS і веб) мовою JavaScript з використанням бібліотеки React.

Ключова ідея: **ви пишете компоненти React, але замість HTML-елементів у DOM вони рендеряться у справжні нативні віджети платформи**. Компонент `<View>` на Android стає `android.view.ViewGroup`, а на iOS — `UIView`. Кнопка, текст, поле введення, список — усе це нативні елементи, які користувач не відрізнить від написаних на Kotlin чи Swift.

Гасло React Native — **«Learn once, write anywhere»** («Вивчи один раз — пиши будь-де»). Зверніть увагу: не «write once, run anywhere». Розробники React Native не обіцяють, що один і той самий код ідеально запрацює на всіх платформах без змін. Вони обіцяють, що знання React (компоненти, пропси, стан, хуки) ви зможете застосовувати всюди, а платформні відмінності враховувати там, де це потрібно.

### Коротка історія

| Рік | Подія |
|---|---|
| 2013 | Facebook відкриває React — бібліотеку для вебінтерфейсів. |
| 2013–2014 | Внутрішній хакатон Facebook: прототип рендерингу React-компонентів у нативні iOS-елементи. |
| 2015 | Публічний реліз React Native для iOS (березень), згодом — для Android (вересень). |
| 2016–2018 | Швидке зростання: Instagram, Skype, Discord, Tesla, Walmart використовують RN. З'являється Expo. |
| 2018 | Meta оголошує масштабний переробіток архітектури (майбутня «New Architecture»). |
| 2019 | Представлено Hermes — JS-рушій, оптимізований для мобільних пристроїв. |
| 2022–2024 | Нова архітектура стає стабільною; з версії 0.76 вона увімкнена за замовчуванням. |
| сьогодні | Нова архітектура і Hermes — стандарт; стара архітектура (міст) поступово видаляється з кодової бази. Expo — офіційно рекомендований спосіб створення нових проєктів. |

Сьогодні на React Native працюють (повністю або частково) застосунки Facebook, Instagram, Messenger, Microsoft Office/Outlook/Teams (частина екранів), Discord, Shopify, Coinbase, Bloomberg та багато інших.

:::note
React Native не «конвертує» JavaScript у Java/Kotlin чи Swift. JavaScript-код виконується в JS-рушії всередині застосунку, а React Native керує нативними елементами інтерфейсу на основі того, що «намалював» ваш React-код.
:::

## 2. Як працює React Native

### Потоки виконання

У типовому RN-застосунку працюють кілька потоків:

- **Головний (UI) потік** — нативний потік платформи. Він малює інтерфейс, обробляє дотики, анімації. Якщо його заблокувати — застосунок «зависне».
- **JS-потік** — тут виконується ваш JavaScript: React, бізнес-логіка, обробники подій, запити до мережі.
- **Фонові потоки** — для обчислення розмітки (layout) за допомогою рушія **Yoga** (реалізація Flexbox на C++), роботи нативних модулів тощо.

Головне правило продуктивності: **JS-потік і UI-потік повинні якомога менше чекати один на одного**. Якщо JS-потік зайнятий важкими обчисленнями, інтерфейс перестає реагувати на дотики — кнопки «не натискаються».

### Стара архітектура: міст (Bridge)

До Нової архітектури взаємодія JS і нативної частини відбувалась через **міст**:

1. JS-код формує повідомлення (наприклад, «створи View з такими стилями» або «виклич метод камери»).
2. Повідомлення **серіалізуються в JSON** і групуються в пакети (batch).
3. Пакети асинхронно передаються через міст у нативну частину, там **десеріалізуються** та виконуються.
4. Відповіді та події (дотики, прокручування) йдуть тим самим шляхом назад.

Недоліки такого підходу:

- **Асинхронність усього**: неможливо синхронно отримати, наприклад, розмір елемента — лише через колбек.
- **Накладні витрати на серіалізацію JSON**: при великій кількості повідомлень (швидке прокручування довгого списку, анімації) міст стає «вузьким горлом».
- **Усі нативні модулі ініціалізуються під час старту** застосунку, навіть ті, що ніколи не знадобляться, — це сповільнює запуск.

### Нова архітектура (New Architecture)

Нова архітектура складається з кількох частин:

| Компонент | Що це | Що дає |
|---|---|---|
| **JSI** (JavaScript Interface) | Легкий C++ API, через який JS-рушій може напряму тримати посилання на C++-об'єкти та викликати їхні методи. | Немає JSON-серіалізації; можливі **синхронні** виклики; основа для всього іншого. |
| **Fabric** | Новий рендерер (система відображення) інтерфейсу, написаний на C++ і спільний для платформ. | Синхронне вимірювання розмітки, підтримка конкурентних можливостей React 18+ (`useTransition`, Suspense), більш передбачуваний рендеринг. |
| **TurboModules** | Нове покоління нативних модулів. | **Ліниве завантаження** (модуль ініціалізується лише при першому зверненні), швидші виклики через JSI. |
| **Codegen** | Генератор коду, який за типізованою специфікацією створює C++-«клей» між JS і нативним кодом. | Типобезпечна взаємодія, менше ручного коду й помилок. |

Схематично:

```text
Стара архітектура:
  JS  ──(JSON, async, batch)──►  Bridge  ──►  Native (Java/ObjC)

Нова архітектура:
  JS  ◄──── JSI (C++ посилання, sync/async) ────►  C++ ядро (Fabric, TurboModules)  ◄──►  Native (Kotlin/Swift)
```

:::tip[Що це означає для вас як розробника]
Для прикладного програміста, який пише компоненти та використовує готові бібліотеки, Нова архітектура майже непомітна: ви так само пишете `<View>` і `<Text>`. Вона увімкнена за замовчуванням у сучасних версіях RN і в Expo. Відмінності важливі, коли ви пишете власні нативні модулі або обираєте сторонні бібліотеки (перевіряйте, що бібліотека підтримує New Architecture — на сайті [reactnative.directory](https://reactnative.directory) це позначено).
:::

### Hermes

**Hermes** — JavaScript-рушій, створений Meta спеціально для React Native. Він увімкнений за замовчуванням.

Особливості Hermes:

- **Попередня компіляція в байт-код (AOT)**: під час збирання застосунку JS-код компілюється в байт-код Hermes. На пристрої не треба розбирати (парсити) і компілювати JS — звідси **швидший старт**.
- **Менше споживання пам'яті** та менший розмір застосунку порівняно з JavaScriptCore або V8.
- Підтримка налагодження через Chrome DevTools протокол (React Native DevTools).

Під час розробки код з Metro (збирач, bundler) передається на пристрій, а в релізній збірці — вже готовий байт-код.

### Metro — збирач (bundler)

**Metro** — це збирач JavaScript для React Native (аналог Webpack/Vite у вебі). Він:

- збирає всі ваші модулі в один бандл (bundle);
- транспілює сучасний JS/JSX через Babel;
- роздає бандл на пристрій/емулятор під час розробки;
- забезпечує **Fast Refresh** — миттєве оновлення інтерфейсу при збереженні файлу зі збереженням стану компонентів.

## 3. React для вебу vs React Native

### Що залишається тим самим

- Компоненти (функціональні), JSX.
- Пропси, стан, хуки: `useState`, `useEffect`, `useContext`, `useReducer`, `useMemo`, `useCallback`, `useRef`, власні хуки.
- Односпрямований потік даних, підняття стану, контекст.
- Бібліотеки, не прив'язані до DOM: Redux/Zustand, TanStack Query, date-fns, валідація форм тощо.
- `fetch`, `Promise`, `async/await`, `setTimeout`, `console.log`.

### Що змінюється

| Аспект | React (веб) | React Native |
|---|---|---|
| Рендеринг | `react-dom` → DOM у браузері | `react-native` → нативні віджети |
| Контейнер | `<div>`, `<section>`, `<header>` | `<View>` |
| Текст | `<p>`, `<span>`, `<h1>` або текст будь-де | `<Text>` — **текст можна писати тільки всередині `<Text>`** |
| Зображення | `<img src="...">` | `<Image source={...}>` |
| Поле введення | `<input>`, `<textarea>` | `<TextInput>` |
| Кнопка/клік | `<button onClick>` | `<Pressable onPress>`, `<Button onPress>` |
| Прокручування | автоматично (overflow сторінки) | лише в `<ScrollView>`, `<FlatList>` |
| Списки | `array.map()` | `<FlatList>`, `<SectionList>` (віртуалізація) |
| Стилі | CSS-файли, класи, CSS-модулі, Tailwind | JS-об'єкти, `StyleSheet.create()`, без каскаду |
| Одиниці | `px`, `em`, `rem`, `%`, `vh` | числа без одиниць (density-independent pixels), `%` |
| Розмітка | block/inline, Flexbox, Grid | лише Flexbox (за замовчуванням `flexDirection: 'column'`) |
| Маршрутизація | React Router, URL у браузері | React Navigation (стек екранів, вкладки), Expo Router |
| API платформи | Web API: `window`, `document`, `localStorage` | Нативні модулі: камера, геолокація, AsyncStorage, сповіщення |
| Налагодження | DevTools браузера | React Native DevTools, логи Metro, емулятор |
| Розгортання | завантажити файли на хостинг | зібрати APK/AAB/IPA, пройти модерацію в магазинах |

### Приклад: той самий компонент у вебі та в RN

```jsx title="Web: Greeting.jsx"
import './Greeting.css';

export default function Greeting({ name }) {
  return (
    <div className="card">
      <h1>Привіт, {name}!</h1>
      <button onClick={() => alert('Клік!')}>Натисни</button>
    </div>
  );
}
```

```jsx title="React Native: Greeting.js"
import { View, Text, Pressable, StyleSheet, Alert } from 'react-native';

export default function Greeting({ name }) {
  return (
    <View style={styles.card}>
      <Text style={styles.title}>Привіт, {name}!</Text>
      <Pressable style={styles.button} onPress={() => Alert.alert('Клік!')}>
        <Text style={styles.buttonText}>Натисни</Text>
      </Pressable>
    </View>
  );
}

const styles = StyleSheet.create({
  card: {
    padding: 16,
    borderRadius: 12,
    backgroundColor: '#fff',
  },
  title: {
    fontSize: 24,
    fontWeight: 'bold', // назви властивостей — camelCase
  },
  button: {
    marginTop: 12,
    padding: 12,
    backgroundColor: '#2563eb',
    borderRadius: 8,
  },
  buttonText: {
    color: '#fff', // колір тексту задається на <Text>, а не на кнопці
    textAlign: 'center',
  },
});
```

Що варто помітити:

1. Компоненти імпортуються з пакета `react-native`, а не є вбудованими тегами.
2. Немає `className` — є проп `style`, який приймає об'єкт або масив об'єктів.
3. Властивості стилів записуються в camelCase (`backgroundColor`, а не `background-color`), значення розмірів — числа.
4. Немає `alert()` з браузера — є `Alert.alert()` з нативним діалогом.
5. Текст кнопки обгорнуто в `<Text>`.

### Стилі без CSS

У React Native **немає CSS-рушія**. Стилі — це звичайні JS-об'єкти з обмеженим набором властивостей, схожим на CSS:

- **Немає каскаду та селекторів**: не можна написати `.card p { ... }`. Кожен компонент стилізується явно.
- **Обмежене успадкування**: лише вкладені `<Text>` успадковують текстові стилі від батьківського `<Text>`. `<View>` нічого не передає дочірнім елементам — `color` на `<View>` просто не працює.
- **Немає псевдокласів** `:hover`, `:focus` — стан натискання обробляється через `Pressable` (`({ pressed }) => ...`).
- **Немає медіазапитів** — замість них хук `useWindowDimensions()`.

```jsx
// Масив стилів: пізніші перекривають попередні, falsy-значення ігноруються
<View style={[styles.card, isActive && styles.cardActive]} />
```

### Події

| Веб | React Native |
|---|---|
| `onClick` | `onPress` |
| `onDoubleClick` / `contextmenu` | `onLongPress` |
| `onChange` (event.target.value) | `onChangeText` (одразу рядок) |
| `onSubmit` форми | `onSubmitEditing` у `TextInput` (форм як таких немає) |
| `onScroll` | `onScroll` у `ScrollView`/`FlatList` |

```jsx
<TextInput
  value={title}
  onChangeText={setTitle}            // отримуємо рядок, а не подію
  onSubmitEditing={handleSave}       // натискання «Enter/Готово» на клавіатурі
/>
```

### Немає DOM і Web API

У React Native **немає** `document`, `window.localStorage`, `document.getElementById`, `querySelector`. Бібліотеки, які працюють з DOM (наприклад, jQuery, Bootstrap, більшість UI-бібліотек для вебу, react-router-dom), у RN **не працюють**.

Замість них — нативні модулі:

| Веб | React Native / Expo |
|---|---|
| `localStorage` | `@react-native-async-storage/async-storage` |
| `navigator.geolocation` | `expo-location` |
| `<input type="file" accept="image/*">` | `expo-image-picker` |
| `getUserMedia()` | `expo-camera` |
| `window.innerWidth` | `useWindowDimensions()` |
| Cookies для токенів | `expo-secure-store` |

`fetch`, `console`, `setTimeout`, `Promise`, `JSON`, `URL` — доступні.

### Маршрутизація

У вебі навігація базується на URL і історії браузера. У мобільних застосунках немає адресного рядка; користувач рухається **стеком екранів** (екран відкривається «поверх» попереднього, кнопка «Назад» повертає), **вкладками** внизу (bottom tabs) або **бічним меню** (drawer). Для цього використовують **React Navigation** або **Expo Router** (файлова маршрутизація, схожа на Next.js). Детально — на окремій лекції.

## 4. Expo vs React Native CLI

Є два основні способи створити й розробляти RN-застосунок.

### React Native CLI («голий» React Native)

Проєкт створюється командою `npx @react-native-community/cli init MyApp`. Ви отримуєте папки `android/` та `ios/` з нативними проєктами, які самі налаштовуєте в Android Studio та Xcode. Для збирання під iOS **обов'язково потрібен Mac**.

### Expo

**Expo** — це платформа та набір інструментів поверх React Native:

- **Expo SDK** — понад 50 готових модулів (камера, геолокація, сповіщення, файли, сенсори, безпечне сховище тощо), протестованих разом.
- **Expo Go** — застосунок для телефона, у якому можна запускати свій проєкт, просто відсканувавши QR-код, без збирання.
- **Development builds** — власна версія «Expo Go» з вашими нативними бібліотеками.
- **Continuous Native Generation (CNG)** і **prebuild** — папки `android/` та `ios/` генеруються автоматично з `app.json` і плагінів конфігурації; їх не треба комітити й підтримувати вручну.
- **EAS** (Expo Application Services) — хмарне збирання (`eas build`, зокрема під iOS без Mac), публікація в магазини (`eas submit`), оновлення «по повітрю» (`eas update`).
- **Expo Router** — файлова маршрутизація.

| Критерій | Expo (managed workflow) | React Native CLI |
|---|---|---|
| Старт проєкту | 1 команда, працює за хвилини | потрібні Android Studio/Xcode, JDK, налаштування |
| Запуск на телефоні | Expo Go + QR-код | збирання й встановлення через USB |
| Нативні модулі | Expo SDK + будь-які бібліотеки через development build | будь-які, вручну |
| Нативний код | через config plugins або `prebuild` | повний доступ одразу |
| Збирання iOS без Mac | так, через EAS Build | ні |
| OTA-оновлення | `eas update` | сторонні рішення |
| Рекомендація команди RN | **офіційно рекомендований фреймворк** для нових проєктів | для специфічних випадків / вбудовування RN в існуючий нативний застосунок |

:::note
Документація React Native прямо рекомендує починати нові проєкти з фреймворку, і таким фреймворком є Expo. Міф «Expo — це обмежена іграшка» застарів: завдяки development builds і config plugins у Expo-проєкті можна використати практично будь-яку нативну бібліотеку.
:::

У цьому модулі ми працюємо з **Expo (managed workflow)** і актуальною версією Expo SDK.

## 5. React Native серед інших підходів

| Підхід | Мова | Інтерфейс | Плюси | Мінуси |
|---|---|---|---|---|
| **Нативна розробка** | Kotlin (Android), Swift (iOS) | нативні віджети (Jetpack Compose, SwiftUI) | максимальна продуктивність, повний доступ до API одразу після релізу ОС | дві окремі кодові бази, дві команди, вища вартість |
| **React Native** | JavaScript/TypeScript | нативні віджети | одна кодова база, знання React, велика екосистема npm, OTA-оновлення | місток між JS і нативом (зменшений у New Architecture), іноді потрібен нативний код |
| **Flutter** | Dart | власний рушій рендерингу (Impeller) — малює все сам | однаковий вигляд на всіх платформах, висока продуктивність анімацій, гарячий перезапуск | нова мова Dart, віджети «імітують» нативні, більший розмір застосунку |
| **Kotlin Multiplatform** | Kotlin | спільна логіка, UI — нативний або Compose Multiplatform | спільна бізнес-логіка з нативним UI | менша екосистема, потрібні знання обох платформ |
| **Ionic / Capacitor** | HTML/CSS/JS (будь-який фреймворк) | WebView | повторне використання вебкоду й навичок | інтерфейс — вебсторінка у WebView, відчутно повільніший і «не нативний» |
| **PWA** | HTML/CSS/JS | браузер | без магазинів, миттєве оновлення, одна кодова база з сайтом | обмежений доступ до API (особливо на iOS), немає повноцінної присутності в магазинах |

Коли обирати React Native:

- команда вже знає JavaScript/React;
- потрібен застосунок під обидві платформи з нативним відчуттям;
- важливо швидко випускати оновлення (OTA);
- є вебверсія на React і хочеться ділити логіку.

Коли варто подумати про інше:

- складні 3D-ігри (краще Unity/Unreal);
- застосунок інтенсивно використовує найновіші API однієї платформи (AR, віджети, wearables) — нативна розробка;
- потрібен ідентичний піксель-у-піксель інтерфейс на всіх платформах — Flutter;
- достатньо простого вебзастосунку з офлайн-кешем — PWA.

## 6. Анатомія Expo-проєкту і перший компонент

### Створення проєкту

```bash
npx create-expo-app@latest my-places --template blank
cd my-places
npx expo start
```

Шаблон `blank` створює мінімальний проєкт без навігації — ідеальний для навчання. (Шаблон за замовчуванням містить Expo Router і TypeScript.)

### Структура

```text
my-places/
├── assets/            # іконка, сплеш-екран, зображення
│   ├── icon.png
│   ├── adaptive-icon.png
│   ├── splash-icon.png
│   └── favicon.png
├── node_modules/
├── App.js             # кореневий компонент застосунку
├── app.json           # конфігурація Expo: назва, іконка, дозволи, плагіни
├── index.js           # точка входу: реєструє App
├── package.json       # залежності та скрипти
└── .gitignore
```

| Файл | Призначення |
|---|---|
| `index.js` | Викликає `registerRootComponent(App)` — реєструє кореневий компонент для нативної частини. Зазвичай не змінюється. |
| `App.js` | Кореневий компонент. З нього починається ваш інтерфейс. |
| `app.json` | Метадані застосунку: `name`, `slug`, `version`, `orientation`, `icon`, `splash`, налаштування `ios`/`android`, `plugins`. На основі нього генеруються нативні проєкти. |
| `package.json` | Залежності (`expo`, `react`, `react-native`, `expo-status-bar`) і скрипти `start`, `android`, `ios`, `web`. |
| `assets/` | Статичні ресурси, які підключаються через `require('./assets/...')`. |

```js title="index.js"
import { registerRootComponent } from 'expo';
import App from './App';

// Реєструє App як кореневий компонент і налаштовує середовище
// однаково для Expo Go та нативних збірок
registerRootComponent(App);
```

### Перший компонент

```jsx title="App.js"
import { StatusBar } from 'expo-status-bar';
import { StyleSheet, Text, View } from 'react-native';

export default function App() {
  return (
    <View style={styles.container}>
      <Text style={styles.title}>Мої місця</Text>
      <Text>Щоденник місць, які я відвідав</Text>
      <StatusBar style="auto" />
    </View>
  );
}

const styles = StyleSheet.create({
  container: {
    flex: 1,                 // зайняти весь доступний простір екрана
    backgroundColor: '#fff',
    alignItems: 'center',    // по горизонталі (поперечна вісь)
    justifyContent: 'center' // по вертикалі (головна вісь — column)
  },
  title: {
    fontSize: 28,
    fontWeight: '700',
    marginBottom: 8,
  },
});
```

Розберемо:

- `View` з `flex: 1` розтягується на весь екран. Без `flex: 1` контейнер займав би лише висоту свого вмісту.
- `alignItems` і `justifyContent` працюють як у CSS Flexbox, але **головна вісь за замовчуванням вертикальна**.
- `StatusBar` з пакета `expo-status-bar` керує кольором системного рядка стану (годинник, батарея).

### Компонування власних компонентів

```jsx title="components/Greeting.js"
import { Text } from 'react-native';

export default function Greeting({ name }) {
  return <Text>Привіт, {name}!</Text>;
}
```

```jsx title="App.js (фрагмент)"
import Greeting from './components/Greeting';

// ...
<Greeting name="студенте" />
```

:::caution[Типова помилка новачка]
```jsx
<View>Привіт</View>
```
призведе до помилки: «Text strings must be rendered within a `<Text>` component». Будь-який текст, навіть пробіл між змінними в JSX, має бути всередині `<Text>`.
:::

### Як запускається застосунок

1. `npx expo start` запускає Metro і показує QR-код.
2. Expo Go на телефоні (або емулятор) завантажує JS-бандл з Metro по мережі.
3. Нативна частина (вже вбудована в Expo Go) запускає Hermes, виконує бандл.
4. React будує дерево компонентів, Fabric створює нативні елементи, Yoga розраховує їхні розміри й позиції.
5. При збереженні файлу Metro надсилає оновлений модуль — спрацьовує Fast Refresh.

## Підсумки

- React Native дозволяє писати мобільні застосунки на React, які рендеряться в **справжні нативні компоненти**, а не у WebView.
- JS виконується в рушії **Hermes**; взаємодія з нативною частиною в сучасних версіях іде через **JSI**, рендеринг — через **Fabric**, нативні модулі — **TurboModules**. Нова архітектура увімкнена за замовчуванням.
- Від React для вебу залишаються компоненти, JSX, пропси, стан і хуки. Змінюються примітиви (`View`, `Text`, `Image`, `TextInput`), стилізація (JS-об'єкти, лише Flexbox, без каскаду), події (`onPress`, `onChangeText`), навігація та доступ до API пристрою.
- **Expo** — офіційно рекомендований спосіб створення RN-застосунків: швидкий старт, Expo Go, SDK модулів, EAS для збирання й публікації.
- React Native — компроміс між вартістю розробки (одна кодова база) і нативністю (справжні нативні віджети).
