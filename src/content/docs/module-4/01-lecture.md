## Мета заняття

- Зрозуміти, чим серверна частина (backend) вебзастосунку відрізняється від клієнтської (frontend) і які задачі вона розв'язує.
- Розібратися, як PHP обробляє HTTP-запит: від браузера через вебсервер до інтерпретатора і назад.
- Ознайомитися з історією PHP та можливостями сучасних версій (PHP 8.x).
- Порівняти PHP з іншими серверними технологіями (Node.js, Python, Java, C#).
- Встановити та налаштувати робоче середовище: XAMPP (Windows), XAMPP або Homebrew (macOS), вбудований сервер `php -S`, VS Code з розширенням PHP Intelephense.
- Написати перший PHP-скрипт і навчитися запускати його у браузері та в терміналі.

## 1. Клієнт, сервер і backend-розробка

У попередніх модулях ви писали HTML, CSS і JavaScript — код, який **виконується в браузері користувача**. Це клієнтська частина, або **frontend**. Але більшість реальних вебзастосунків не може обійтися лише нею:

- інтернет-магазин має десь зберігати товари, замовлення і користувачів;
- форма реєстрації повинна перевірити, що email ще не зайнятий, і безпечно зберегти пароль;
- блог має показувати однакові пости всім відвідувачам, а не лише тому, хто їх створив у своєму `localStorage`.

Усе це — задачі **серверної частини (backend)**: програми, що працює на сервері, приймає запити від клієнтів, виконує бізнес-логіку, звертається до бази даних і повертає відповідь.

### Модель «клієнт — сервер»

```text
┌──────────────┐   HTTP-запит (GET /index.php)    ┌──────────────────────────┐
│   Браузер    │ ───────────────────────────────► │         Сервер           │
│   (клієнт)   │                                  │  вебсервер + PHP + БД    │
│              │ ◄─────────────────────────────── │                          │
└──────────────┘   HTTP-відповідь (200 OK, HTML)   └──────────────────────────┘
```

- **Клієнт** ініціює взаємодію: надсилає **запит (request)**.
- **Сервер** чекає на запити, обробляє їх і повертає **відповідь (response)**.
- Спілкуються вони за протоколом **HTTP** (HyperText Transfer Protocol) або його захищеною версією **HTTPS**.

Детально будову HTTP-запиту (метод, заголовки, тіло) ми розберемо на практичній 6, коли почнемо обробляти форми. Зараз достатньо знати, що запит містить **метод** (`GET`, `POST`…), **адресу ресурсу** (`/index.php?page=2`) і **заголовки**, а відповідь — **код статусу** (`200`, `404`, `500`…), заголовки і **тіло** (найчастіше HTML або JSON).

### Що робить backend

| Задача | Приклад |
|---|---|
| Генерація сторінок | Сформувати HTML зі списком товарів, взятих із бази даних |
| Обробка форм | Прийняти дані реєстрації, перевірити їх, зберегти |
| Робота з даними | Читати й записувати в базу даних (MySQL, PostgreSQL), файли |
| Автентифікація і авторизація | Перевірити пароль, запам'ятати користувача, обмежити доступ |
| API | Віддавати дані у форматі JSON для фронтенду чи мобільного застосунку |
| Інтеграції | Надіслати лист, прийняти оплату, звернутися до стороннього сервісу |
| Безпека | Не довіряти даним від клієнта, захищатися від атак |

:::note[Головне правило backend-розробника]
**Клієнту не можна довіряти.** Будь-яку перевірку на JavaScript можна вимкнути, будь-яке поле форми — підробити через DevTools або надіслати запит узагалі без браузера (наприклад, через `curl`). Тому всі важливі перевірки обов'язково дублюються на сервері. До цього правила ми повертатимемося впродовж усього модуля.
:::

### Статичні і динамічні сторінки

**Статична сторінка** — це файл `.html`, який вебсервер віддає «як є». Усі відвідувачі отримують однаковий вміст, поки хтось не відредагує файл вручну.

**Динамічна сторінка** формується програмою в момент запиту. Файл `index.php` не віддається браузеру — його **виконує** інтерпретатор PHP, а браузер отримує лише **результат виконання** (зазвичай HTML). Тому користувач ніколи не бачить ваш PHP-код, навіть через «Переглянути код сторінки».

## 2. Як працює PHP

### PHP — мова серверних сценаріїв

**PHP** (рекурсивний акронім *PHP: Hypertext Preprocessor*) — інтерпретована мова загального призначення, створена спеціально для веброзробки. Ключові властивості:

- **інтерпретована**: вихідний код компілюється в проміжний байт-код (opcodes) і виконується віртуальною машиною **Zend Engine** — окремого кроку «збирання» немає, достатньо зберегти файл і оновити сторінку;
- **динамічно типізована** з можливістю суворих перевірок типів (`declare(strict_types=1)`, типізовані параметри й властивості);
- **вбудовується в HTML**: PHP-код можна вставляти безпосередньо в розмітку;
- має величезну **стандартну бібліотеку** функцій для рядків, масивів, дат, файлів, мережі, баз даних;
- кросплатформна: працює на Linux, Windows, macOS.

### Життєвий цикл запиту

Розглянемо, що відбувається, коли користувач відкриває `http://localhost/blog/index.php`:

```text
1. Браузер ──► HTTP-запит GET /blog/index.php ──► вебсервер (Apache / Nginx)
2. Вебсервер бачить розширення .php і передає файл інтерпретатору PHP
      (модуль mod_php в Apache або окремий процес PHP-FPM)
3. PHP компілює файл у байт-код (або бере готовий з кешу OPcache)
4. Zend Engine виконує байт-код:
      - звертається до бази даних, читає файли, обчислює...
      - усе, що виводиться (echo, HTML поза <?php ?>), потрапляє у буфер відповіді
5. PHP повертає вебсерверу результат (HTML) і заголовки
6. Вебсервер надсилає браузеру HTTP-відповідь 200 OK
7. Скрипт завершено, уся пам'ять (змінні, масиви, з'єднання) звільнена
```

| Компонент | Роль | Приклади |
|---|---|---|
| Вебсервер | Приймає HTTP-з'єднання, віддає статичні файли, передає `.php` інтерпретатору | Apache HTTP Server, Nginx, Caddy |
| Інтерпретатор PHP | Виконує скрипт | `mod_php` (модуль Apache), PHP-FPM (FastCGI Process Manager) |
| OPcache | Кешує скомпільований байт-код, щоб не компілювати файл при кожному запиті | вбудоване розширення PHP |
| СУБД | Зберігає дані між запитами | MySQL / MariaDB, PostgreSQL, SQLite |

### Архітектура «нічого спільного» (share-nothing)

Дуже важлива особливість класичного PHP: **кожен запит обробляється з чистого аркуша**. Скрипт стартує, виконується і завершується, а всі змінні зникають. Наступний запит (навіть від того самого користувача) нічого не «пам'ятає» про попередній.

```php title="counter.php"
<?php
$visits = 0;
$visits++;
echo "Кількість відвідувань: $visits";
// Скільки б разів ви не оновлювали сторінку — завжди буде 1
```

Наслідки:

- **Плюси**: простота (немає витоків пам'яті між запитами), надійність (помилка в одному запиті не «кладе» весь сервер), легке горизонтальне масштабування (можна поставити кілька серверів).
- **Мінуси**: стан доводиться зберігати **поза скриптом** — у файлах, базі даних, сесіях, кукі. Саме цим ми й займатимемося в модулі: файл `posts.json` (П6), база даних MySQL (П8–П9), сесії та кукі (П10).

:::tip[Порівняння з Node.js]
У Node.js сервер — це **один довготривалий процес**: змінна, оголошена на верхньому рівні модуля, «живе» між запитами. У PHP так не буває (якщо не використовувати спеціальні рушії на кшталт Swoole, RoadRunner чи FrankenPHP у worker-режимі). Пам'ятайте про це, коли переходите з однієї мови на іншу.
:::

## 3. Історія PHP і сучасні версії

| Рік | Подія |
|---|---|
| 1994–1995 | Расмус Лердорф (Rasmus Lerdorf) пише набір CGI-скриптів на C «Personal Home Page Tools» для свого сайту і публікує їх. |
| 1998 | PHP 3: ядро переписують Зеєв Сураскі та Енді Гутманс; назва стає рекурсивним акронімом *PHP: Hypertext Preprocessor*. |
| 2000 | PHP 4 на новому рушії Zend Engine. PHP стає найпопулярнішою мовою для вебу. |
| 2004 | PHP 5: повноцінне ООП, винятки, згодом — PDO для роботи з базами даних. |
| 2010-ті | Поява Composer (менеджер пакетів), стандартів PSR, фреймворків Symfony і Laravel. Версія PHP 6 так і не вийшла. |
| 2015 | PHP 7: новий рушій, приблизно вдвічі вища швидкодія, скалярні типи параметрів і типи повернення, оператори `??` і `<=>`. |
| 2020 | PHP 8.0: іменовані аргументи, `match`, nullsafe-оператор `?->`, union-типи, JIT-компілятор. |
| 2021 | PHP 8.1: переліки (enum), `readonly`-властивості, тип `never`, синтаксис first-class callable. |
| 2022 | PHP 8.2: `readonly`-класи, типи `true`/`false`/`null`, застарілі динамічні властивості. |
| 2023–2025 | PHP 8.3 (типізовані константи класів, `json_validate()`), 8.4 (property hooks, `array_find()`), 8.5 (оператор конвеєра `\|>`). |

Кожна мінорна версія PHP отримує активну підтримку близько двох років і ще два роки — виправлення безпеки. Актуальний графік підтримки — на сторінці [php.net/supported-versions](https://www.php.net/supported-versions.php). **У курсі ми використовуємо PHP 8.2 або новішу.**

:::caution[Застарілі матеріали]
В інтернеті дуже багато прикладів PHP-коду 2005–2015 років. Ознаки застарілого коду: функції `mysql_*` (видалені в PHP 7), `mysqli` без підготовлених запитів, виведення `$_GET` без екранування, `md5()` для паролів, відсутність типів. Якщо бачите таке — шукайте сучасніший приклад.
:::

### Де використовується PHP

- За даними сервісу W3Techs, PHP використовують близько трьох чвертей сайтів, серверну мову яких вдалося визначити.
- **WordPress** — система керування вмістом (CMS), на якій працює значна частина всіх сайтів інтернету, — написана на PHP. Так само Drupal, Joomla, MediaWiki (рушій Вікіпедії), Magento, PrestaShop, OpenCart.
- **Фреймворки**: Laravel (найпопулярніший), Symfony, Yii, CodeIgniter, Slim.
- PHP історично використовувався у Facebook (згодом на його основі створено мову Hack), Slack, Etsy, Wikipedia.

Для вас як майбутніх розробників це означає: PHP-вакансій багато, особливо в агенціях, e-commerce і на фрилансі, а поріг входження відносно невисокий.

## 4. PHP серед інших серверних технологій

| Технологія | Мова | Сильні сторони | Слабкі сторони |
|---|---|---|---|
| **PHP** (+ Laravel/Symfony) | PHP | простий старт і хостинг, величезна екосистема CMS, share-nothing модель | неоднорідна стандартна бібліотека (історичні назви функцій), багато застарілих туторіалів |
| **Node.js** (+ Express, NestJS) | JavaScript/TypeScript | одна мова на фронтенді й бекенді, асинхронність, WebSocket | однопотоковість (важкі обчислення блокують сервер), швидкозмінна екосистема |
| **Python** (+ Django, FastAPI) | Python | читабельність, data science і ML, «батарейки» Django | повільніший за компільовані мови, GIL |
| **Java** (+ Spring) | Java/Kotlin | швидкодія, надійність, великі корпоративні системи | багатослівність, складніша інфраструктура |
| **C#** (+ ASP.NET Core) | C# | швидкодія, потужні інструменти Microsoft | складніший поріг входження |
| **Go** | Go | висока продуктивність, проста конкурентність, один бінарний файл | менше готових рішень для типових вебсайтів |

Чому для навчання backend ми обираємо PHP:

1. **Мінімум інфраструктури**: встановив XAMPP — і вже маєш вебсервер, PHP і базу даних.
2. **Прозорість HTTP**: PHP-скрипт відповідає рівно на один запит, тому легко побачити, як працюють методи, форми, кукі, сесії — без «магії» фреймворків.
3. **Дешевий хостинг**: PHP + MySQL підтримує практично будь-який хостинг, навіть безкоштовний (ми скористаємося цим на П14).
4. Ідеї, які ви вивчите (HTTP, SQL, сесії, безпека, REST), однакові для всіх серверних мов.

## 5. Робоче середовище

Для розробки на PHP потрібні: **інтерпретатор PHP**, **вебсервер** (або вбудований сервер PHP), пізніше — **СУБД MySQL/MariaDB**, і **редактор коду**.

### Варіант 1 (основний). XAMPP на Windows

**XAMPP** — безкоштовний пакет від Apache Friends, що містить **A**pache, **M**ariaDB (сумісна з MySQL), **P**HP і **P**erl, а також phpMyAdmin — вебінтерфейс для бази даних. Літера **X** означає кросплатформність.

1. Завантажте інсталятор з [apachefriends.org](https://www.apachefriends.org) — версію з **PHP 8.2 або новішою**.
2. Встановлюйте в `C:\xampp` (не в `C:\Program Files` — там можуть бути проблеми з правами на запис).
3. У списку компонентів достатньо **Apache, MySQL, PHP, phpMyAdmin**.
4. Запустіть **XAMPP Control Panel** і натисніть **Start** навпроти **Apache** (MySQL знадобиться з П8).
5. Відкрийте у браузері `http://localhost` — має з'явитися стартова сторінка XAMPP.

Структура, яка нас цікавить:

```text
C:\xampp\
├── apache\conf\httpd.conf   # конфігурація Apache (порт, DocumentRoot)
├── htdocs\                  # КОРІНЬ САЙТІВ: усе, що тут, доступне через http://localhost/
│   ├── practice-04\         # → http://localhost/practice-04/
│   └── mini-blog\           # → http://localhost/mini-blog/
├── mysql\                   # MariaDB
├── php\
│   ├── php.exe              # інтерпретатор (можна запускати з терміналу)
│   └── php.ini              # конфігурація PHP
└── xampp-control.exe
```

Файл `C:\xampp\htdocs\practice-04\index.php` відкривається за адресою `http://localhost/practice-04/` (файл `index.php` вебсервер шукає в папці автоматично), а `C:\xampp\htdocs\practice-04\test.php` — за адресою `http://localhost/practice-04/test.php`.

:::caution[Типова проблема: Apache не запускається]
Найчастіша причина — **порт 80 уже зайнятий** іншою програмою (IIS, Skype старих версій, інший вебсервер, VMware). У Control Panel натисніть **Netstat**, щоб побачити, хто тримає порт. Рішення: закрити програму або змінити порт Apache: **Config → Apache (httpd.conf)**, рядок `Listen 80` замінити на `Listen 8080`, і так само `ServerName localhost:8080`. Тоді адреса буде `http://localhost:8080/`.
:::

Щоб запускати PHP з терміналу (наприклад, `php -v`), додайте `C:\xampp\php` у змінну середовища `Path` і перезапустіть термінал.

### Варіант 2. macOS: XAMPP або Homebrew

На macOS можна встановити XAMPP так само (корінь сайтів — `/Applications/XAMPP/htdocs/`). Альтернатива, з якою зручніше працювати з терміналу, — менеджер пакетів **Homebrew**:

```bash
# встановлення PHP (і пізніше — MySQL)
brew install php
brew install mysql

# перевірка
php -v
```

У цьому варіанті Apache не потрібен — використовуємо **вбудований вебсервер PHP**.

### Вбудований вебсервер `php -S`

PHP має власний простий вебсервер для розробки. Він працює на будь-якій ОС, де встановлено PHP (у тому числі з XAMPP на Windows):

```bash
cd ~/htdocs/practice-04        # перейти в папку проєкту
php -S localhost:8000          # запустити сервер
```

```text
[Fri Feb 13 10:15:02 2026] PHP 8.4.x Development Server (http://localhost:8000) started
```

Тепер `http://localhost:8000/` відкриває `index.php` з поточної папки. Зупинити сервер — `Ctrl+C`. У терміналі видно журнал кожного запиту і помилки — це зручно для налагодження.

| | Apache з XAMPP | `php -S` |
|---|---|---|
| Запуск | кнопка Start у Control Panel | команда в терміналі в папці проєкту |
| Адреса | `http://localhost/назва-папки/` | `http://localhost:8000/` |
| Підтримка `.htaccess` | так | ні |
| Кілька проєктів одночасно | так, кожен у своїй папці `htdocs` | один сервер на один порт |
| Для продакшну | так (з налаштуванням) | **ні, лише для розробки** |

:::danger
Вбудований сервер однопотоковий і не призначений для роботи в інтернеті. Ніколи не використовуйте `php -S` на реальному хостингу.
:::

### Запуск PHP у терміналі (CLI)

PHP — не лише вебмова. Скрипт можна виконати напряму в терміналі (Command Line Interface):

```bash
php -v                 # версія PHP
php -m                 # список увімкнених розширень (шукайте mbstring, pdo_mysql, json)
php --ini              # де лежить php.ini
php hello.php          # виконати файл
php -r 'echo 2 ** 10;' # виконати один вираз (на Windows — подвійні лапки)
php -a                 # інтерактивний режим (REPL)
```

CLI зручний, щоб швидко перевірити роботу функції чи виразу без браузера.

## 6. Конфігурація PHP: `php.ini`

Поведінку PHP визначає файл **`php.ini`**. Дізнатися, який саме файл використовується, можна командою `php --ini` або функцією `phpinfo()`.

```php title="info.php"
<?php
phpinfo(); // виводить сторінку з повною інформацією про PHP: версія, php.ini, розширення, змінні
```

:::caution
Файл з `phpinfo()` розкриває багато інформації про сервер. Використовуйте його лише локально і **ніколи не залишайте на хостингу**.
:::

Ключові налаштування для розробки:

| Директива | Значення для розробки | Значення для продакшну | Пояснення |
|---|---|---|---|
| `display_errors` | `On` | `Off` | Показувати помилки прямо на сторінці |
| `error_reporting` | `E_ALL` | `E_ALL` | Які помилки фіксувати (усі) |
| `log_errors` | `On` | `On` | Записувати помилки в журнал |
| `date.timezone` | `Europe/Kyiv` | `Europe/Kyiv` | Часовий пояс для функцій дати |
| `default_charset` | `UTF-8` | `UTF-8` | Кодування відповіді за замовчуванням |
| `upload_max_filesize` | `8M` | за потреби | Максимальний розмір завантажуваного файлу |

Після зміни `php.ini` **перезапустіть Apache** (Stop → Start у XAMPP) або сервер `php -S`.

Чому помилки на продакшні треба приховувати? Повідомлення на кшталт `Warning: include(/var/www/site/config.php)...` розкривають зловмисникові структуру сервера. На локальному комп'ютері ж, навпаки, кожна помилка має бути видимою — це ваш головний інструмент налагодження.

### Рівні помилок

| Рівень | Приклад | Що відбувається |
|---|---|---|
| **Fatal error** / необроблений `Error` | виклик неіснуючої функції, помилка типу | скрипт зупиняється |
| **Parse error** | пропущена `;` або дужка | скрипт навіть не запускається |
| **Warning** | читання неіснуючого ключа масиву, `include` відсутнього файлу | скрипт продовжує роботу |
| **Notice** / **Deprecated** | використання застарілої функції | скрипт продовжує роботу |

```text
Parse error: syntax error, unexpected identifier "echo", expecting "," or ";"
in C:\xampp\htdocs\practice-04\index.php on line 4
```

Уміння прочитати таке повідомлення — **тип помилки, опис, файл, рядок** — перша навичка PHP-розробника. Зверніть увагу: при пропущеній `;` PHP часто вказує на **наступний** рядок, бо саме там зрозумів, що щось не так.

## 8. Перший скрипт

### Теги PHP

PHP-інтерпретатор обробляє лише код між тегами `<?php` і `?>`. Усе, що поза ними, виводиться без змін.

```php title="hello.php"
<?php
echo 'Привіт, світе!';
```

Правила:

- Кожна інструкція закінчується крапкою з комою `;`.
- Якщо файл містить **лише PHP-код**, закриваючий тег `?>` **не ставлять**. Так ви уникнете випадкових пробілів і порожніх рядків після нього, які потраплять у відповідь (і знову — *headers already sent*). Це вимога стандарту оформлення коду PSR-12.
- Коротка форма `<?= $x ?>` — це скорочення для `<?php echo $x; ?>`. Її зручно використовувати в шаблонах.

### Виведення: `echo`, `print`, `var_dump`, `print_r`

| Конструкція | Призначення | Приклад |
|---|---|---|
| `echo` | вивести один чи кілька рядків (найуживаніше) | `echo 'Сума: ', $sum;` |
| `print` | те саме, але лише один аргумент і повертає 1 | `print 'Текст';` |
| `var_dump()` | налагодження: тип і значення, рекурсивно | `var_dump($user);` |
| `print_r()` | налагодження: зручне для людини виведення масивів | `print_r($list);` |
| `var_export()` | виводить значення у вигляді валідного PHP-коду | `var_export($config);` |

```php title="debug.php"
<?php
$price = 199.5;
$tags = ['php', 'backend'];

var_dump($price);   // float(199.5)
var_dump($tags);    // array(2) { [0]=> string(3) "php" [1]=> string(7) "backend" }

echo '<pre>';       // <pre> зберігає переноси рядків у браузері
print_r($tags);
echo '</pre>';
```

:::note
`string(7) "backend"` — це довжина в **байтах**. Для кирилиці в UTF-8 одна літера займає 2 байти, тому `var_dump('Київ')` покаже `string(8)`. До цього ми повернемося на наступній лекції, коли говоритимемо про функції `mb_*`.
:::

### PHP усередині HTML

Головна особливість PHP — змішування з розміткою. Сервер виконає PHP-фрагменти і поверне браузеру чистий HTML:

```php title="index.php"
<?php
$title = 'Моя перша PHP-сторінка';
$hour = (int) date('G'); // поточна година 0–23
$greeting = $hour < 12 ? 'Доброго ранку' : 'Доброго дня';
?>
<!doctype html>
<html lang="uk">
<head>
    <meta charset="utf-8">
    <title><?= $title ?></title>
</head>
<body>
    <h1><?= $title ?></h1>
    <p><?= $greeting ?>! Зараз <?= date('H:i') ?>.</p>
    <p>Версія PHP на сервері: <?= PHP_VERSION ?></p>

    <ul>
        <?php for ($i = 1; $i <= 3; $i++): ?>
            <li>Пункт <?= $i ?></li>
        <?php endfor; ?>
    </ul>
</body>
</html>
```

Що отримає браузер (подивіться через `Ctrl+U`):

```html
<!doctype html>
<html lang="uk">
<head>
    <meta charset="utf-8">
    <title>Моя перша PHP-сторінка</title>
</head>
<body>
    <h1>Моя перша PHP-сторінка</h1>
    <p>Доброго дня! Зараз 14:05.</p>
    <p>Версія PHP на сервері: 8.4.3</p>
    <ul>
        <li>Пункт 1</li>
        <li>Пункт 2</li>
        <li>Пункт 3</li>
    </ul>
</body>
</html>
```

Жодного рядка PHP — лише результат. Зверніть увагу на **альтернативний синтаксис** керуючих конструкцій (`for (...):` … `endfor;`, а також `if:`/`endif;`, `foreach:`/`endforeach;`). У шаблонах він читається набагато краще, ніж фігурні дужки, розкидані між тегами.

:::caution[Не відкривайте .php як файл]
Якщо відкрити `index.php` подвійним кліком, адреса буде `file:///C:/xampp/...` і браузер покаже сирий код або запропонує завантажити файл. PHP-сторінки завжди відкривають **через вебсервер**: `http://localhost/...`.
:::

### Коментарі і стиль коду

```php
<?php
// однорядковий коментар
# теж однорядковий (рідко використовується)

/*
 * Багаторядковий коментар
 */

/**
 * DocBlock — документаційний коментар перед функцією.
 * Його читає Intelephense і показує як підказку.
 *
 * @param float $price Ціна товару
 * @return float Ціна з ПДВ
 */
function withVat(float $price): float
{
    return $price * 1.2;
}
```

Базові правила оформлення (стандарт [PSR-12](https://www.php-fig.org/psr/psr-12/), який підтримує Intelephense):

- відступ — **4 пробіли**;
- фігурна дужка функції — з нового рядка, дужка `if`/`for` — у тому самому рядку;
- ключові слова (`true`, `false`, `null`) — малими літерами;
- змінні й функції — `camelCase` або `snake_case` (у межах проєкту — однаково). Вбудовані функції PHP використовують `snake_case` (`array_map`, `str_contains`), тож у наших хелперах ми теж оберемо `snake_case`.

## Підсумки

- **Backend** — програма на сервері, що обробляє HTTP-запити, працює з даними і повертає відповідь. Клієнту довіряти не можна — перевірки дублюються на сервері.
- **PHP** — інтерпретована мова для вебу; скрипт виконується на сервері, а браузер отримує лише результат (HTML, JSON).
- Ланцюжок: браузер → вебсервер (Apache/Nginx) → PHP (mod_php / PHP-FPM, OPcache) → відповідь. Кожен запит обробляється з нуля (**share-nothing**), стан зберігається у файлах, БД, сесіях.
- Сучасний PHP (8.x) — типізація, `match`, іменовані аргументи, enum, `readonly`. Код без типів і з `mysql_*` — застарілий.
- Середовище курсу: **XAMPP** (Windows; корінь сайтів `C:\xampp\htdocs`), на macOS — XAMPP або Homebrew + `php -S localhost:8000`; редактор VS Code + **PHP Intelephense**.
- На локальній машині `display_errors=On`, `error_reporting=E_ALL`; на продакшні помилки приховуються і пишуться в журнал.
- Код PHP — між `<?php` і `?>`; у файлах лише з PHP закриваючий тег не ставлять; `<?= ?>` — скорочене виведення.

## Домашнє завдання

1. Встановіть на домашньому комп'ютері XAMPP (або PHP через Homebrew на macOS), VS Code і PHP Intelephense. Переконайтеся, що `php -v` у терміналі показує версію 8.2 або новішу.
2. У php.ini встановіть `display_errors=On`, `error_reporting=E_ALL`, `date.timezone=Europe/Kyiv`; перезапустіть сервер і перевірте значення через `phpinfo()`.
3. Створіть `htdocs/hello/index.php` — сторінку-візитку: ваше ім'я, група, поточна дата (`date('d.m.Y')`), версія PHP (`PHP_VERSION`) і список із 3 улюблених технологій, виведений циклом `for` в альтернативному синтаксисі.
4. Навмисно зробіть у файлі синтаксичну помилку (видаліть `;`), прочитайте повідомлення і виправте.

**Що здати:** скриншот сторінки `http://localhost/hello/` і скриншот терміналу з `php -v`.
