## 1. Три шари вебсторінки

Будь-яку сучасну вебсторінку зручно уявляти як три шари, кожен з яких відповідає за своє:

| Шар | Технологія | Відповідає за | Аналогія з будинком |
|---|---|---|---|
| Структура | **HTML** | Зміст і смисл: заголовки, абзаци, кнопки, форми | Стіни, двері, вікна |
| Представлення | **CSS** | Вигляд: кольори, шрифти, розташування, анімації | Фарба, шпалери, меблі |
| Поведінка | **JavaScript** | Реакція на дії користувача, обчислення, робота з даними | Електрика, вимикачі, ліфт |

HTML і CSS — **декларативні** мови: ми описуємо, *що* має бути на сторінці і *як* воно виглядає. JavaScript — повноцінна **мова програмування**: ми описуємо, *що робити* — послідовність дій, умови, повторення, реакцію на події.

Що вміє JavaScript на сторінці:

- реагувати на дії користувача — натискання, введення тексту, прокручування, наведення миші;
- змінювати вміст і вигляд сторінки без перезавантаження;
- перевіряти дані у формі до відправлення;
- завантажувати дані з сервера (новини, погоду, курси валют) і показувати їх;
- зберігати налаштування в браузері (наприклад, темну тему);
- створювати ігри, анімації, графіки, карти.

:::note[Прогресивне покращення]
Добра практика — будувати сторінку так, щоб її основний зміст був доступний уже на рівні HTML, оформлення додавав CSS, а JavaScript робив її зручнішою та інтерактивнішою. Якщо скрипт не завантажився, користувач усе одно має побачити зміст.
:::

### Чи можна обійтися без JavaScript?

Частину «інтерактивності» вже вміє CSS: `:hover`, `:focus`, переходи `transition`, анімації `@keyframes`, навіть розкривні блоки через `<details>`. Правило просте: **якщо задачу можна розв'язати на HTML/CSS — розв'язуйте на HTML/CSS**. JavaScript потрібен там, де треба *пам'ятати стан*, *обчислювати* або *реагувати на дані*: лічильник кліків, кошик, перевірка пароля, фільтр списку.

## 2. Коротка історія JavaScript

| Рік | Подія |
|---|---|
| 1995 | Брендан Ейк (Brendan Eich) у компанії Netscape за 10 днів створює мову для браузера Netscape Navigator. Робочі назви — Mocha, LiveScript. |
| 1995 | Мову перейменовують на **JavaScript** — переважно з маркетингових причин, бо тоді була популярна Java. |
| 1997 | Мову стандартизує організація Ecma International — з'являється стандарт **ECMAScript** (ES1). |
| 2009 | ES5: строгий режим, методи масивів, JSON. З'являється Node.js — JavaScript виходить за межі браузера. |
| 2015 | **ES6 (ES2015)** — найбільше оновлення: `let`/`const`, стрілкові функції, класи, модулі, проміси. |
| з 2016 | Щорічні оновлення: ES2016, ES2017 … Нові можливості додаються невеликими порціями щороку. |

:::caution[JavaScript ≠ Java]
Це дві зовсім різні мови з різними ідеями, синтаксисом і сферами застосування. Схожі лише назви. Фраза «Java та JavaScript — це як car і carpet» добре це передає.
:::

### ECMAScript і рушії

- **ECMAScript** — це *стандарт*, специфікація мови: які є типи, оператори, як працюють функції.
- **JavaScript** — реалізація цього стандарту (плюс можливості середовища — наприклад, робота зі сторінкою в браузері).
- **Рушій JavaScript (JS engine)** — програма, яка виконує код:

| Рушій | Де використовується |
|---|---|
| V8 | Google Chrome, Microsoft Edge, Opera, Node.js |
| SpiderMonkey | Mozilla Firefox |
| JavaScriptCore | Apple Safari |

Сучасні рушії не просто «читають рядок за рядком»: вони аналізують код і компілюють його «на льоту» (JIT-компіляція, Just-In-Time) у машинні інструкції, тому JavaScript сьогодні працює дуже швидко.

## 3. Де виконується JavaScript

| Середовище | Що робить JavaScript | Приклади |
|---|---|---|
| **Браузер** (frontend) | Інтерактивність сторінок, вебзастосунки | Gmail, Google Docs, YouTube |
| **Сервер** (backend) | Обробка запитів, робота з базами даних | Node.js, Deno, Bun |
| **Мобільні застосунки** | Кросплатформні застосунки | React Native |
| **Десктоп** | Програми для Windows/macOS/Linux | VS Code, Discord, Slack (Electron) |
| **Інше** | Скрипти автоматизації, ігри, IoT | Розширення браузера, ігри на Canvas |

У нашому курсі ми рухаємося так: спочатку JavaScript у браузері (цей і наступний модулі), потім бібліотеки та фреймворки (React, Angular, Next.js) і нарешті мобільна розробка на React Native.

### Що може і чого не може JavaScript у браузері

З міркувань безпеки код на сторінці працює в «пісочниці» (sandbox):

- ✅ може змінювати *свою* сторінку, реагувати на події, надсилати запити на сервер, зберігати невеликі дані в браузері;
- ❌ не може довільно читати файли на комп'ютері (лише ті, які користувач сам обрав через `<input type="file">`);
- ❌ не може читати вміст інших вкладок і сайтів;
- ❌ не може без дозволу користувача отримати доступ до камери, мікрофона, геолокації.

## 4. Інструменти розробника і консоль

У кожному сучасному браузері є **інструменти розробника (DevTools)**. Відкрити їх:

| Дія | Windows / Linux | macOS |
|---|---|---|
| Відкрити DevTools | `F12` або `Ctrl + Shift + I` | `Cmd + Option + I` |
| Відразу відкрити консоль | `Ctrl + Shift + J` | `Cmd + Option + J` |
| Через меню | ПКМ на сторінці → «Переглянути код» (Inspect) | так само |

Основні вкладки, які нам знадобляться:

| Вкладка | Для чого |
|---|---|
| **Elements** | HTML-структура та CSS-стилі сторінки (вже знайома з CSS) |
| **Console** | Виконання JavaScript і повідомлення від скриптів |
| **Sources** | Файли скриптів, точки зупинки для налагодження |
| **Network** | Запити, які надсилає сторінка |

### Консоль як калькулятор і «пісочниця»

У консолі можна просто вводити код і натискати `Enter` — результат з'явиться одразу:

```js
2 + 2 * 2          // 6
'Привіт, ' + 'світ' // 'Привіт, світ'
10 / 3             // 3.3333333333333335
Math.round(10 / 3) // 3
new Date()         // поточні дата і час
```

Можна навіть змінити відкриту сторінку:

```js
document.title = 'Мене змінив JavaScript';
document.body.style.background = 'lavender';
```

:::tip[Корисні клавіші консолі]
- `↑` / `↓` — попередні команди;
- `Shift + Enter` — новий рядок без виконання (для кількох рядків коду);
- `Ctrl + L` або кнопка 🚫 — очистити консоль.
:::

:::note
Зміни, зроблені з консолі, діють лише до перезавантаження сторінки — ви змінюєте сторінку у своєму браузері, а не файли на сервері. Тому зламати так чужий сайт неможливо.
:::

## 5. Перший скрипт: підключення до сторінки

Консоль зручна для експериментів, але справжній код зберігають у файлах. Підключити JavaScript до HTML-сторінки можна двома способами.

### Спосіб 1. Вбудований скрипт

```html title="index.html"
<!DOCTYPE html>
<html lang="uk">
<head>
  <meta charset="UTF-8">
  <title>Мій перший скрипт</title>
</head>
<body>
  <h1>Привіт!</h1>

  <script>
    console.log('Скрипт працює!');
  </script>
</body>
</html>
```

### Спосіб 2. Зовнішній файл (рекомендовано)

```text
first-js/
├── index.html
├── style.css
└── script.js
```

```html title="index.html"
<!DOCTYPE html>
<html lang="uk">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Мій перший скрипт</title>
  <link rel="stylesheet" href="style.css">
  <script src="script.js" defer></script>
</head>
<body>
  <h1>Привіт!</h1>
</body>
</html>
```

```js title="script.js"
console.log('Скрипт підключено із зовнішнього файлу');
```

Чому зовнішній файл кращий:

- HTML, CSS і JS лежать окремо — так само, як ми виносимо стилі в `style.css`;
- один скрипт можна підключити до кількох сторінок;
- браузер **кешує** файл і не завантажує його повторно.

:::caution
Тег `<script>` з атрибутом `src` не може одночасно містити код усередині — він буде проігнорований:

```html
<script src="script.js">
  alert('Це не виконається!');
</script>
```
:::

### Де розміщувати `<script>` і навіщо `defer`

Браузер читає HTML згори донизу. Коли він натрапляє на звичайний `<script>`, то **зупиняє** побудову сторінки, завантажує й виконує скрипт і лише потім продовжує. Звідси дві проблеми:

1. Сторінка довше залишається порожньою.
2. Скрипт у `<head>` не «бачить» елементів, які ще не створені нижче.

| Варіант | Як працює | Коли використовувати |
|---|---|---|
| `<script>` в кінці `<body>` | Виконується, коли весь HTML вище вже є | Класичний підхід, працює завжди |
| `<script defer>` у `<head>` | Завантажується паралельно, виконується **після** побудови HTML, у порядку підключення | **Рекомендований** спосіб |
| `<script async>` | Завантажується паралельно, виконується одразу, щойно завантажився | Незалежні скрипти: аналітика, реклама |

У цьому курсі ми будемо підключати скрипти так: `<script src="script.js" defer></script>` у `<head>`.

## 6. Перші команди та діалогові вікна

### `console.log` — головний друг розробника

```js title="script.js"
console.log('Привіт із консолі!');
console.log('Сума:', 5 + 7);
console.log('Сьогодні:', new Date().toLocaleDateString('uk-UA'));

console.warn('Це попередження');  // жовте повідомлення
console.error('Це помилка');      // червоне повідомлення
```

`console.log` нічого не показує користувачу на сторінці — повідомлення бачить лише розробник у консолі. Це основний спосіб перевірити, що код дійшов до певного місця і які значення має.

### Діалогові вікна браузера

| Функція | Що робить | Що повертає |
|---|---|---|
| `alert('текст')` | Показує повідомлення з кнопкою «OK» | нічого |
| `prompt('питання', 'за замовчуванням')` | Просить ввести текст | введений рядок або `null`, якщо натиснули «Скасувати» |
| `confirm('питання')` | Питання з кнопками «OK» і «Скасувати» | `true` або `false` |

```js title="script.js"
const name = prompt('Як тебе звати?', 'Студент');
alert('Привіт, ' + name + '!');

const likesCss = confirm('Тобі подобається CSS?');
console.log('Подобається CSS:', likesCss);
```

У цьому прикладі з'явилося слово `const` — так ми створюємо **змінну**, тобто іменовану «коробку» для значення. Детально змінні, типи даних і оператори ми розберемо на першій лекції модуля «Основи JavaScript», а поки досить розуміти: `const name = …` — «запам'ятати значення під іменем `name`».

:::caution[Діалоги — лише для навчання]
`alert`, `prompt` і `confirm` блокують сторінку, поки користувач не відповість, і виглядають у кожному браузері по-своєму — стилізувати їх CSS неможливо. На реальних сайтах замість них використовують форми та власні модальні вікна. Нам вони зручні лише для перших експериментів.
:::

### Трохи синтаксису

```js
// Однорядковий коментар — браузер його ігнорує

/*
  Багаторядковий коментар.
  Зручно для пояснень і тимчасового «вимикання» коду.
*/

console.log('Кожна інструкція — окремий рядок');
console.log('Крапку з комою в кінці ставимо завжди');
```

Основні правила, які варто запам'ятати вже зараз:

- JavaScript **чутливий до регістру**: `console.log` працює, а `Console.Log` — ні;
- рядки беремо в лапки: `'одинарні'`, `"подвійні"` або `` `зворотні` `` (про останні — пізніше);
- інструкції виконуються **по черзі, згори донизу**;
- відступи не впливають на роботу, але роблять код читабельним — форматуйте код як і HTML.

## 7. Перша взаємодія зі сторінкою

Найцікавіше — коли JavaScript змінює сторінку у відповідь на дії користувача. Для цього потрібні три кроки:

1. **Знайти** елемент на сторінці.
2. **Підписатися на подію** — наприклад, натискання (`click`).
3. **Змінити** елемент: текст, стиль або CSS-клас.

### Приклад 1. Кнопка змінює текст

```html title="index.html (фрагмент body)"
<h1 id="title">Привіт!</h1>
<button id="hello-btn">Натисни мене</button>
```

```js title="script.js"
const title = document.querySelector('#title');
const button = document.querySelector('#hello-btn');

button.addEventListener('click', () => {
  title.textContent = 'Ти натиснув кнопку! 🎉';
});
```

Розберемо:

- `document` — об'єкт, що представляє всю сторінку;
- `document.querySelector('#title')` — знаходить перший елемент за **CSS-селектором**. Ті самі селектори, що й у CSS: `#id`, `.class`, `tag`, `nav a`;
- `addEventListener('click', …)` — «коли по кнопці клікнуть, виконай ось цю функцію»;
- `() => { … }` — функція, тобто блок коду, який виконається пізніше, у момент кліку;
- `textContent` — текст усередині елемента.

### Приклад 2. JavaScript + CSS: перемикання теми

Найкращий спосіб змінювати вигляд з JavaScript — **не прописувати стилі в коді, а вмикати й вимикати CSS-класи**. Усі стилі залишаються в CSS, а JS лише керує станом.

```css title="style.css"
body {
  font-family: system-ui, sans-serif;
  background: #ffffff;
  color: #1f2937;
  transition: background 0.3s, color 0.3s;
}

body.dark {
  background: #111827;
  color: #f9fafb;
}

.theme-btn {
  padding: 0.6rem 1.2rem;
  border: none;
  border-radius: 8px;
  background: #7c3aed;
  color: white;
  cursor: pointer;
}
```

```html title="index.html (фрагмент body)"
<h1>Моя сторінка</h1>
<p>Натисни кнопку, щоб змінити тему.</p>
<button class="theme-btn" id="theme-btn">🌙 Темна тема</button>
```

```js title="script.js"
const themeBtn = document.querySelector('#theme-btn');

themeBtn.addEventListener('click', () => {
  document.body.classList.toggle('dark');

  if (document.body.classList.contains('dark')) {
    themeBtn.textContent = '☀️ Світла тема';
  } else {
    themeBtn.textContent = '🌙 Темна тема';
  }
});
```

- `classList.toggle('dark')` — додає клас, якщо його немає, і прибирає, якщо є;
- `classList.contains('dark')` — перевіряє, чи є клас;
- плавність забезпечує вже знайомий нам `transition` у CSS.

| Метод | Що робить |
|---|---|
| `el.classList.add('a')` | Додає клас |
| `el.classList.remove('a')` | Прибирає клас |
| `el.classList.toggle('a')` | Перемикає клас |
| `el.classList.contains('a')` | Перевіряє наявність (`true`/`false`) |

### Приклад 3. Лічильник кліків

```html title="index.html (фрагмент body)"
<p>Кліків: <span id="count">0</span></p>
<button id="plus">+1</button>
<button id="reset">Скинути</button>
```

```js title="script.js"
const countEl = document.querySelector('#count');
let count = 0; // let — змінна, значення якої буде змінюватися

document.querySelector('#plus').addEventListener('click', () => {
  count = count + 1;
  countEl.textContent = count;
});

document.querySelector('#reset').addEventListener('click', () => {
  count = 0;
  countEl.textContent = count;
});
```

Тут JavaScript робить те, чого не вміє CSS: **пам'ятає стан** (кількість кліків) і оновлює сторінку.

:::tip[Стилі через `style` — лише у виняткових випадках]
Можна писати `el.style.color = 'red'`, але так стилі «розмазуються» по JS-коду. Вмикайте класи через `classList`, а `style` використовуйте лише для значень, які обчислюються в коді (наприклад, ширина індикатора прогресу у відсотках).
:::

## 8. Помилки та як їх читати

Помилки — нормальна частина програмування. Важливо вміти їх **читати**. Коли в скрипті помилка, браузер показує в консолі червоне повідомлення з назвою помилки, описом і посиланням на файл і рядок (`script.js:5`). Клік на посилання відкриває потрібне місце у вкладці Sources.

| Помилка | Що означає | Типова причина |
|---|---|---|
| `Uncaught SyntaxError: …` | Код написаний з порушенням правил мови | Незакрита дужка чи лапка, зайвий символ |
| `Uncaught ReferenceError: x is not defined` | Звертання до імені, якого немає | Одрук у назві: `consol.log`, `Title` замість `title` |
| `Uncaught TypeError: Cannot read properties of null` | Намагаємося працювати з елементом, якого не знайдено | Неправильний селектор або скрипт без `defer` виконався раніше, ніж з'явився елемент |
| `Uncaught TypeError: x is not a function` | Викликаємо як функцію те, що нею не є | Одрук у назві методу: `addEventlistener` |

Приклад: ми написали `document.querySelector('#titel')` (одрук), і `querySelector` повернув `null`. Далі `null.textContent = …` дає `TypeError: Cannot set properties of null`. Рішення — перевірити селектор і `id` в HTML.

:::note[Алгоритм дій при помилці]
1. Відкрийте консоль і прочитайте **перше** червоне повідомлення — решта часто є наслідком першої.
2. Перейдіть за посиланням на файл і рядок.
3. Перевірте одруки, регістр, дужки та лапки.
4. Додайте `console.log(...)` перед проблемним рядком, щоб побачити значення.
5. Якщо скрипт «мовчить» — перевірте вкладку Network: чи завантажився `script.js` (помилка 404 означає неправильний шлях у `src`).
:::

## Підсумки

- Вебсторінка — це три шари: HTML (структура), CSS (вигляд) і JavaScript (поведінка).
- JavaScript створено 1995 року; стандарт мови — ECMAScript, який оновлюється щороку. JavaScript і Java — різні мови.
- Код виконує рушій (V8, SpiderMonkey, JavaScriptCore); сьогодні JavaScript працює в браузері, на сервері, у мобільних і десктопних застосунках.
- Консоль DevTools — місце для експериментів і перегляду повідомлень `console.log` та помилок.
- Скрипти підключаємо зовнішнім файлом: `<script src="script.js" defer></script>`.
- Щоб «оживити» сторінку: знаходимо елемент (`querySelector`), слухаємо подію (`addEventListener`) і змінюємо текст або CSS-класи (`textContent`, `classList`).
- Повідомлення про помилки містять тип, опис і рядок — читайте перше з них.
