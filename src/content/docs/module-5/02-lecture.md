## 1. Що таке JSX і як він працює

**JSX** (JavaScript XML) — розширення синтаксису JavaScript, яке дозволяє записувати опис інтерфейсу у вигляді, схожому на HTML, безпосередньо в JavaScript-коді:

```jsx
const greeting = <h1 className="title">Вітаю, студенте!</h1>;
```

Це **не рядок і не HTML**. Браузер такий код не розуміє — перед виконанням його перетворює **транспілятор** (Babel, esbuild або SWC — у Vite цим займається вбудований інструментарій). Результат перетворення — звичайний виклик функції:

```js
// Сучасне перетворення (з React 17, «automatic runtime»)
import { jsx as _jsx } from 'react/jsx-runtime';

const greeting = _jsx('h1', { className: 'title', children: 'Вітаю, студенте!' });
```

У старих проєктах ви побачите класичну форму `React.createElement('h1', { className: 'title' }, 'Вітаю, студенте!')` — саме тому раніше в кожному файлі з JSX потрібно було писати `import React from 'react'`. Зараз цей імпорт **не потрібен**.

Функція `jsx()` повертає **React-елемент** — простий об'єкт-опис:

```js
{ type: 'h1', props: { className: 'title', children: 'Вітаю, студенте!' }, key: null }
```

Вкладені теги стають вкладеними викликами:

```jsx
<div className="card">
  <h2>React</h2>
  <p>Бібліотека для UI</p>
</div>
```

```js
_jsxs('div', {
  className: 'card',
  children: [
    _jsx('h2', { children: 'React' }),
    _jsx('p', { children: 'Бібліотека для UI' })
  ]
});
```

### Чому JSX, а не шаблони

Інші фреймворки (Vue, Angular) використовують HTML-шаблони з власними директивами: `v-for`, `*ngIf`. У JSX немає спеціальної «мови шаблонів»: умови — це звичайні `if`, `&&` і тернарний оператор, цикли — `map`. Тобто все, що ви знаєте про JavaScript, працює в розмітці. Розмітка і логіка компонента знаходяться поруч, бо вони тісно пов'язані: кнопка і її обробник, список і дані для нього.

:::tip[Спробуйте самі]
Онлайн-пісочниця [Babel REPL](https://babeljs.io/repl) (пресет React) показує, на що перетворюється будь-який JSX. Вставте туди кілька прикладів з цієї лекції — так значно легше зрозуміти, «що насправді відбувається».
:::

## 2. Правила синтаксису JSX

### Правило 1. Один кореневий елемент

Вираз JSX має повертати **один** елемент — бо функція не може повернути два значення одночасно:

```jsx
// ❌ Помилка: Adjacent JSX elements must be wrapped in an enclosing tag
return (
  <h1>Заголовок</h1>
  <p>Текст</p>
);
```

Рішення — обгорнути в елемент або у **фрагмент** (Fragment), який не створює зайвого вузла в DOM:

```jsx
// ✅ Короткий синтаксис фрагмента
return (
  <>
    <h1>Заголовок</h1>
    <p>Текст</p>
  </>
);
```

Повна форма `<Fragment>` (імпорт з `'react'`) потрібна, коли фрагменту треба передати `key` у списку:

```jsx
import { Fragment } from 'react';

{terms.map(term => (
  <Fragment key={term.id}>
    <dt>{term.word}</dt>
    <dd>{term.meaning}</dd>
  </Fragment>
))}
```

:::note
Круглі дужки навколо багаторядкового JSX після `return` не обов'язкові синтаксично, але без них JavaScript автоматично вставить крапку з комою одразу після `return`, якщо розмітка почнеться з нового рядка, — і функція поверне `undefined`. Тому завжди пишіть `return (` на одному рядку.
:::

### Правило 2. Усі теги закриваються

У HTML дозволено `<br>`, `<img src="...">`, `<input>`. У JSX кожен тег має бути закритий — явно або самозакриваючим слешем:

```jsx
<img src="/logo.png" alt="Логотип" />
<br />
<input type="text" />
<div className="spacer" />   {/* порожній div теж можна самозакрити */}
```

### Правило 3. Атрибути в camelCase і зарезервовані слова

JSX перетворюється на JavaScript-об'єкти, тому імена атрибутів підпорядковуються правилам JS:

| HTML | JSX | Причина |
|---|---|---|
| `class` | `className` | `class` — зарезервоване слово JS |
| `for` (у `<label>`) | `htmlFor` | `for` — зарезервоване слово JS |
| `onclick` | `onClick` | Події — у camelCase |
| `tabindex` | `tabIndex` | camelCase |
| `maxlength` | `maxLength` | camelCase |
| `readonly` | `readOnly` | camelCase |
| `stroke-width` (SVG) | `strokeWidth` | camelCase замість дефісів |
| `aria-label`, `data-id` | `aria-label`, `data-id` | **Винятки**: `aria-*` і `data-*` пишуться як у HTML |

### Правило 4. Значення атрибутів: рядки і вирази

```jsx
<input type="email" placeholder="you@example.com" />  {/* рядок — у лапках */}
<input maxLength={50} />                               {/* число — у фігурних дужках */}
<button disabled={isLoading}>Надіслати</button>        {/* вираз */}
<input required />                                     {/* те саме, що required={true} */}
<img src={user.avatarUrl} alt={`Аватар ${user.name}`} />
```

:::caution[Типова помилка]
`maxLength="50"` передасть **рядок** `"50"`, а `disabled="false"` — непорожній рядок, тобто кнопка буде **заблокована**! Для логічних і числових значень використовуйте фігурні дужки: `disabled={false}`.
:::

### Правило 5. Атрибут `style` — це об'єкт

```jsx
// HTML: <p style="color: red; font-size: 18px; margin-top: 8px">
<p style={{ color: 'red', fontSize: 18, marginTop: '8px' }}>Увага!</p>
```

- Зовнішні фігурні дужки — «тут JavaScript-вираз», внутрішні — літерал об'єкта.
- Властивості CSS — у camelCase: `fontSize`, `backgroundColor`, `borderRadius`.
- Числа для розмірів автоматично отримують `px` (`fontSize: 18` → `18px`); для безрозмірних властивостей (`lineHeight`, `opacity`, `zIndex`) — ні.

Вбудовані стилі зручні для динамічних значень (ширина прогрес-бару, колір з даних). Для решти використовуйте CSS-класи:

```jsx
<div className="progress">
  <div className="progress__bar" style={{ width: `${percent}%` }} />
</div>
```

### Правило 6. Коментарі

```jsx
return (
  <div>
    {/* Коментар усередині JSX — лише так */}
    <Header />
    <Main
      // однорядковий коментар між атрибутами теж працює
      title="Каталог"
    />
  </div>
);
```

## 3. Вирази у фігурних дужках

Фігурні дужки `{}` — «вікно» з розмітки в JavaScript. Усередині можна написати будь-який **вираз** (expression) — те, що повертає значення:

```jsx
const user = { firstName: 'Олена', lastName: 'Коваль', age: 19 };
const skills = ['HTML', 'CSS', 'JavaScript'];

<section>
  <h2>{user.firstName} {user.lastName}</h2>
  <p>Наступного року буде {user.age + 1}</p>
  <p>Навички: {skills.join(', ')}</p>
  <p>Ініціали: {user.firstName[0]}.{user.lastName[0]}.</p>
  <p>Сьогодні: {new Date().toLocaleDateString('uk-UA')}</p>
  <p>Статус: {user.age >= 18 ? 'повнолітня' : 'неповнолітня'}</p>
</section>
```

А от **інструкції** (statements) — `if`, `for`, `while`, `const x = ...` — усередині `{}` писати не можна. Їх виносять вище, перед `return`:

```jsx
function Price({ value, currency }) {
  // Логіка — до return
  let label;
  if (value === 0) {
    label = 'Безкоштовно';
  } else {
    label = `${value} ${currency}`;
  }

  return <span className="price">{label}</span>;
}
```

### Що React вміє відобразити

| Значення в `{}` | Що з'явиться на екрані |
|---|---|
| Рядок, число | Текст: `{'Привіт'}`, `{42}` |
| React-елемент (JSX) | Відповідний елемент |
| Масив | Усі елементи масиву підряд (потрібні ключі) |
| `true`, `false`, `null`, `undefined` | **Нічого** |
| **`0`**, `NaN` | **«0»**, «NaN» — виводяться як текст! |
| Звичайний об'єкт `{a: 1}` | **Помилка**: Objects are not valid as a React child |
| Функція | Нічого + попередження в консолі |

Остання частина таблиці — джерело частих помилок. Наприклад, `{user}` замість `{user.name}` «зламає» застосунок, а дату треба перетворити на рядок: `{date.toLocaleDateString()}`, а не `{date}`.

## 4. Умовний рендеринг

### Раннє повернення з `if`

Коли залежно від умови компонент виглядає зовсім інакше:

```jsx
function Notifications({ items }) {
  if (items.length === 0) {
    return <p className="muted">Нових сповіщень немає</p>;
  }

  return (
    <ul>
      {items.map(n => <li key={n.id}>{n.text}</li>)}
    </ul>
  );
}
```

Компонент може повернути `null`, якщо нічого не потрібно показувати:

```jsx
function Banner({ visible, text }) {
  if (!visible) return null;
  return <div className="banner">{text}</div>;
}
```

### Тернарний оператор `? :`

Коли треба обрати одне з двох всередині розмітки:

```jsx
<button className={isFollowing ? 'btn btn--secondary' : 'btn btn--primary'}>
  {isFollowing ? 'Відписатися' : 'Підписатися'}
</button>
```

### Логічне `&&`

Коли щось треба показати **або нічого**:

```jsx
{isAdmin && <button>Видалити</button>}
{error && <p className="error">{error}</p>}
```

Це працює, бо `a && b` повертає `b`, якщо `a` істинне, і `a` — якщо хибне; а `false` React не відображає.

:::danger[Пастка з нулем]
```jsx
{messages.length && <Badge count={messages.length} />}
```
Якщо повідомлень немає, `messages.length` дорівнює `0` — і на екрані з'явиться **«0»**, бо нуль React відображає. Завжди робіть ліву частину логічною:
```jsx
{messages.length > 0 && <Badge count={messages.length} />}
```
:::

### Порівняння способів

| Спосіб | Коли використовувати |
|---|---|
| `if` + ранній `return` | Компонент повністю різний для різних станів (завантаження, помилка, порожньо) |
| `? :` | Вибір між двома варіантами всередині розмітки |
| `&&` | Показати або не показати один фрагмент |
| Змінна перед `return` | Логіка складна, кілька гілок — тримаємо JSX чистим |
| Об'єкт-словник | Багато варіантів за ключем: `const icons = { success: '✔', error: '✖' }; {icons[type]}` |

Не захоплюйтеся вкладеними тернарними операторами — `a ? b : c ? d : e` у JSX погано читається. Винесіть логіку в змінну або окремий компонент.

## 5. Списки і ключі

### Рендер масиву через `map`

Масив React-елементів відображається підряд. Тому список зручно будувати методом `map`:

```jsx
const courses = [
  { id: 'js', title: 'JavaScript', hours: 60 },
  { id: 'php', title: 'PHP', hours: 48 },
  { id: 'react', title: 'React', hours: 56 },
];

function CourseList() {
  return (
    <ul>
      {courses.map(course => (
        <li key={course.id}>
          {course.title} — {course.hours} год
        </li>
      ))}
    </ul>
  );
}
```

Перед `map` часто ставлять `filter` або `toSorted` (метод ES2023, що не змінює вихідний масив):

```jsx
{courses
  .filter(c => c.hours >= 50)
  .toSorted((a, b) => a.title.localeCompare(b.title, 'uk'))
  .map(c => <li key={c.id}>{c.title}</li>)}
```

### Правила ключів

Як ми з'ясували на минулій лекції, `key` допомагає React зіставити елементи між рендерами.

1. **`key` ставиться на зовнішній елемент усередині `map`**, а не на вкладений.
2. Ключ має бути **унікальним серед сусідів** (у двох різних списках ключі можуть повторюватися).
3. Ключ має бути **стабільним**: той самий елемент — той самий ключ при кожному рендері.
4. `key` — службовий атрибут: компонент **не отримає** його в пропсах. Якщо id потрібен всередині — передайте окремо: `<Item key={x.id} id={x.id} />`.

Звідки брати ключі:

| Джерело | Оцінка |
|---|---|
| `id` з бази даних або API | Найкращий варіант |
| Унікальне поле (email, slug, артикул) | Добре |
| `crypto.randomUUID()` **під час створення** елемента (наприклад, при додаванні завдання) | Добре |
| Індекс масиву `index` | Лише якщо список статичний: ніколи не сортується, не фільтрується і елементи не вставляються/видаляються |
| `Math.random()` або `crypto.randomUUID()` **під час рендеру** | Погано: ключ щоразу новий, React перестворює всі елементи і губить їхній стан |

```jsx
// ❌ ключ на вкладеному елементі — попередження "Each child in a list should have a unique key"
{courses.map(c => (
  <li>
    <span key={c.id}>{c.title}</span>
  </li>
))}

// ❌ ключ генерується при кожному рендері
{courses.map(c => <li key={Math.random()}>{c.title}</li>)}
```

## 6. Функціональні компоненти

### Оголошення компонента

**Компонент** — це JavaScript-функція, яка повертає JSX (або `null`). Дві обов'язкові умови:

1. Назва починається з **великої літери** (PascalCase): `ProductCard`, `UserAvatar`.
2. Функція повертає те, що React уміє відобразити.

```jsx
function Avatar() {
  return <img className="avatar" src="https://i.pravatar.cc/80?img=5" alt="Аватар" />;
}

// Або стрілковою функцією — різниці для React немає
const Avatar = () => (
  <img className="avatar" src="https://i.pravatar.cc/80?img=5" alt="Аватар" />
);
```

Велика літера — не формальність. За нею JSX-транспілятор відрізняє компонент від HTML-тегу:

```jsx
<avatar />   // → jsx('avatar') — невідомий HTML-тег, React виведе <avatar> у DOM
<Avatar />   // → jsx(Avatar) — виклик вашої функції
```

### Композиція компонентів

Компоненти використовують усередині інших компонентів так само, як HTML-теги:

```jsx
function Profile() {
  return (
    <article className="profile">
      <Avatar />
      <h2>Олена Коваль</h2>
      <p>Студентка групи ПІ-21</p>
    </article>
  );
}

function App() {
  return (
    <main>
      <Profile />
      <Profile />
    </main>
  );
}
```

:::caution[Не оголошуйте компоненти всередині компонентів]
```jsx
function App() {
  function Profile() { /* ... */ }   // ❌
  return <Profile />;
}
```
При кожному рендері `App` створюється **нова** функція `Profile`. Для React це новий тип компонента — він знищить старе піддерево (разом зі станом і фокусом) і створить нове. Оголошуйте компоненти на верхньому рівні модуля.
:::

### Пропси — перше знайомство

Компонент `Profile` вище завжди показує одну людину. Щоб зробити його універсальним, передамо дані **пропсами** (props) — атрибутами JSX, які React збирає в об'єкт і передає першим аргументом функції:

```jsx
function Profile({ name, group, avatarId }) {
  return (
    <article className="profile">
      <img className="avatar" src={`https://i.pravatar.cc/80?img=${avatarId}`} alt={name} />
      <h2>{name}</h2>
      <p>Група {group}</p>
    </article>
  );
}

<Profile name="Олена Коваль" group="ПІ-21" avatarId={5} />
<Profile name="Андрій Мельник" group="ПІ-22" avatarId={12} />
```

Детально пропси, значення за замовчуванням, `children` і композицію розберемо на лекції 4.

### Компоненти у файлах: імпорт і експорт

Зазвичай один компонент — один файл з розширенням `.jsx`, назва файлу збігається з назвою компонента:

```text
src/
├── App.jsx
└── components/
    ├── Avatar.jsx
    └── Profile.jsx
```

```jsx title="src/components/Avatar.jsx"
export default function Avatar({ src, alt }) {
  return <img className="avatar" src={src} alt={alt} />;
}
```

```jsx title="src/components/Profile.jsx"
import Avatar from './Avatar.jsx';

export default function Profile({ name, group, avatarUrl }) {
  return (
    <article className="profile">
      <Avatar src={avatarUrl} alt={name} />
      <h2>{name}</h2>
      <p>Група {group}</p>
    </article>
  );
}
```

| Вид експорту | Експорт | Імпорт | Особливості |
|---|---|---|---|
| За замовчуванням (default) | `export default function Profile()` | `import Profile from './Profile.jsx'` | Один на файл; ім'я при імпорті довільне |
| Іменований (named) | `export function Avatar()` | `import { Avatar } from './Avatar.jsx'` | Кілька на файл; ім'я має збігатися |

У курсі домовимося: **компоненти експортуємо за замовчуванням**, а допоміжні функції й дані (`formatPrice`, `products`) — іменовано.

### Як React запускає застосунок

Точка входу (у проєкті Vite це `src/main.jsx`) створює корінь і рендерить головний компонент:

```jsx title="src/main.jsx"
import { StrictMode } from 'react';
import { createRoot } from 'react-dom/client';
import App from './App.jsx';

createRoot(document.getElementById('root')).render(
  <StrictMode>
    <App />
  </StrictMode>
);
```

`StrictMode` — службовий компонент, який **у режимі розробки** вмикає додаткові перевірки: зокрема, викликає функції компонентів двічі, щоб виявити «нечисті» компоненти. У production-збірці він нічого не робить.

## 7. Компоненти мають бути чистими

React очікує, що кожен компонент поводиться як **чиста функція** (pure function):

1. **Однакові вхідні дані — однаковий результат.** За тих самих пропсів і стану компонент повертає той самий JSX.
2. **Жодних побічних ефектів під час рендеру.** Компонент не змінює змінні поза собою, не змінює отримані пропси, не робить запитів до сервера, не працює з DOM напряму.

```jsx
let guestCount = 0;

// ❌ Нечистий компонент: змінює зовнішню змінну під час рендеру
function Guest() {
  guestCount = guestCount + 1;
  return <p>Гість №{guestCount}</p>;
}
```

У StrictMode цей компонент відрендериться двічі — і ви побачите «Гість №2», «Гість №4», «Гість №6». Правильно — передати номер пропсом:

```jsx
// ✅ Чистий компонент
function Guest({ number }) {
  return <p>Гість №{number}</p>;
}
```

Що робити з побічними ефектами (запити, таймери, підписки)? Їх виконують у **обробниках подій** (клік, відправлення форми) або, якщо ефект не пов'язаний з конкретною подією, — у хуку `useEffect` (лекція 7).

Локальні змінні, створені всередині компонента під час рендеру, змінювати можна — це не порушує чистоти:

```jsx
function TagList({ tags }) {
  const items = [];               // локальний масив — створюється щоразу заново
  for (const tag of tags) {
    items.push(<li key={tag}>#{tag}</li>);
  }
  return <ul>{items}</ul>;
}
```

## 8. Безпека JSX і типові помилки

### Автоматичне екранування

React автоматично **екранує** (escapes) усі значення, вставлені через `{}`. Якщо користувач введе як ім'я рядок `<img src=x onerror="alert(1)">`, на екрані з'явиться саме цей текст, а не виконається скрипт. Це захищає від XSS-атак (Cross-Site Scripting) «за замовчуванням» — на відміну від `innerHTML`.

Якщо потрібно вставити готовий HTML (наприклад, статтю з CMS), існує навмисно незручний атрибут:

```jsx
<div dangerouslySetInnerHTML={{ __html: articleHtml }} />
```

Назва попереджає: використовуйте його лише з HTML, якому довіряєте або який пройшов очищення (бібліотека DOMPurify).

### Типові помилки

| Помилка | Наслідок | Як правильно |
|---|---|---|
| `class="card"` | Попередження Invalid DOM property `class` | `className="card"` |
| Два сусідні елементи в `return` | Синтаксична помилка | Обгорнути у `<>...</>` |
| `<img src="...">` без слеша | Синтаксична помилка | `<img src="..." />` |
| `style="color: red"` | Помилка: style prop expects an object | `style={{ color: 'red' }}` |
| `{user}` (об'єкт) | Objects are not valid as a React child | `{user.name}` |
| `{count && <Badge />}` при `count = 0` | На екрані «0» | `{count > 0 && <Badge />}` |
| `onClick={handleClick()}` | Функція викликається під час рендеру, а не по кліку | `onClick={handleClick}` або `onClick={() => handleClick(id)}` |
| `function card() {}` → `<card />` | Відображається як невідомий HTML-тег | Назва з великої літери: `Card` |
| Немає `key` у `map` | Попередження і помилки оновлення | `key={item.id}` на зовнішньому елементі |
| `return` і JSX з нового рядка | Компонент повертає `undefined` | `return (` на одному рядку |

## Підсумки

- **JSX** — синтаксичне розширення JavaScript, яке транспілюється у виклики `jsx()` і повертає React-елементи — звичайні об'єкти-описи.
- Правила JSX: один кореневий елемент (або фрагмент `<>`), усі теги закриті, атрибути в camelCase, `className` і `htmlFor`, `style` — об'єкт.
- У `{}` можна вставити будь-який вираз. `true/false/null/undefined` не відображаються, а `0` — відображається.
- Умовний рендеринг: ранній `return`, тернарний оператор, `&&` (з логічною лівою частиною).
- Списки будуються через `map`; кожен елемент отримує унікальний серед сусідів і стабільний `key`.
- **Функціональний компонент** — функція з назвою з великої літери, що повертає JSX. Компоненти мають бути **чистими**: без побічних ефектів під час рендеру.

## Контрольні питання

1. На що перетворюється JSX під час збирання? Чому сьогодні не потрібно писати `import React from 'react'`?
2. Чому компонент не може повернути два сусідні елементи без обгортки? Що таке фрагмент і коли потрібна повна форма `<Fragment>`?
3. Чому в JSX використовуються `className` і `htmlFor`?
4. Як записати вбудований стиль `background-color: #eee; padding: 10px` у JSX?
5. Що відобразить React для значень `false`, `null`, `0`, `'0'`, `[1, 2]`, `{ a: 1 }`?
6. Чим відрізняється вираз від інструкції? Чому `if` не можна писати всередині `{}`?
7. Яка небезпека запису `{items.length && <List />}`?
8. Чому індекс масиву — поганий ключ для списку, який можна сортувати?
9. Чому назва компонента має починатися з великої літери?
10. Що означає «компонент має бути чистим»? Як StrictMode допомагає знаходити нечисті компоненти?
