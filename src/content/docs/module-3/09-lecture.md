- Зрозуміти подієво-орієнтовану модель роботи браузера: хто генерує події, коли виконуються обробники.

- Розібратися з об'єктом події: `type`, `target`, `currentTarget`, властивості подій миші й клавіатури.

- Скасовувати дії за замовчуванням (`preventDefault`) і правильно обробляти форми.

## 1. Подієво-орієнтована модель браузера

До цього моменту наші скрипти виконувалися «зверху вниз»: браузер завантажував `app.js`, виконував усі інструкції — і на цьому все. Справжній інтерфейс так не працює: він **чекає** на дії користувача і реагує на них. Такий підхід називається **подієво-орієнтованим програмуванням** (event-driven programming).

**Подія** (event) — це сигнал про те, що щось сталося: користувач клацнув кнопку, натиснув клавішу, змінив значення поля, сторінка завантажилася, прийшла відповідь від сервера, закінчилася анімація. **Обробник події** (event handler, event listener) — функція, яку браузер викличе, коли подія станеться.

```js
const button = document.querySelector('button');

button.addEventListener('click', () => {
  console.log('Кнопку натиснуто!');
});

console.log('Обробник призначено');
```

Порядок виведення: спочатку «Обробник призначено», а «Кнопку натиснуто!» — лише тоді (і стільки разів), коли користувач клацне. Ми не викликаємо функцію самі — ми **передаємо** її браузеру, а він викличе її пізніше. Такі функції називають **колбеками** (callback).

### Хто і коли викликає обробники

JavaScript у браузері виконується в **одному потоці**. Коли стається подія, браузер ставить завдання «виклич обробник» у **чергу завдань** (task queue). **Цикл подій** (event loop) бере завдання з черги по одному і виконує їх, коли поточний код завершився.

```text
 Користувач клацає ──► браузер створює подію ──► завдання в черзі
                                                        │
          ┌─────────────────────────────────────────────┘
          ▼
   Цикл подій: «стек викликів порожній?» ──► так ──► виконати обробник
```

Звідси два важливі наслідки:

- Обробник ніколи не перериває код, що вже виконується. Поки працює ваш цикл, жоден клік не буде оброблено.
- Довгий обробник **блокує інтерфейс**: сторінка не прокручується, кнопки не реагують. Обробники мають бути короткими. Детальніше про цикл подій поговоримо в лекції про проміси.

## 2. Способи призначення обробників

### HTML-атрибут `on<подія>`

```html
<button onclick="alert('Привіт')">Натисни</button>
```

Найстаріший спосіб. Код у рядку атрибута, змішування розмітки і логіки, неможливо призначити кілька обробників, проблеми з політикою безпеки CSP. **У сучасному коді не використовується.**

### DOM-властивість `on<подія>`

```js
button.onclick = () => console.log('Перший');
button.onclick = () => console.log('Другий'); // перезаписує перший!
button.onclick = null;                       // видалення
```

Краще за атрибут, але на один елемент можна повісити лише **один** обробник певного типу — нове присвоєння затирає старе.

### `addEventListener` — рекомендований спосіб

```js
function handleClick(event) {
  console.log('Клік!', event.type);
}

button.addEventListener('click', handleClick);
button.addEventListener('click', () => console.log('Ще один обробник'));

// Видалення: потрібно передати ТУ САМУ функцію
button.removeEventListener('click', handleClick);
```

| Спосіб | Кілька обробників | Видалення | Параметри (once, passive…) | Рекомендація |
|---|---|---|---|---|
| HTML-атрибут `onclick="..."` | ні | незручно | ні | не використовувати |
| Властивість `el.onclick = fn` | ні | `el.onclick = null` | ні | допустимо в простих випадках |
| `addEventListener` | так | `removeEventListener` | так | **основний спосіб** |

:::caution[Анонімну функцію неможливо видалити]
```js
button.addEventListener('click', () => console.log('клік'));
button.removeEventListener('click', () => console.log('клік')); // НЕ спрацює
```
Дві однакові на вигляд стрілкові функції — це два різні об'єкти. Якщо обробник потрібно буде видалити, збережіть його в змінну або використовуйте `AbortController` (див. нижче).
:::

### Третій параметр: об'єкт налаштувань

```js
element.addEventListener('click', handler, {
  once: true,      // обробник спрацює один раз і видалиться автоматично
  passive: true,   // обіцянка не викликати preventDefault (для scroll/touch — швидше)
  capture: false,  // обробляти у фазі занурення (див. розділ 4)
  signal,          // AbortSignal: обробник видалиться при controller.abort()
});
```

Параметр `signal` дозволяє видалити одразу кілька обробників, у тому числі анонімних:

```js
const controller = new AbortController();

window.addEventListener('resize', () => console.log('resize'), { signal: controller.signal });
window.addEventListener('scroll', () => console.log('scroll'), { signal: controller.signal });

// Пізніше: видалити обидва обробники однією командою
controller.abort();
```

### Коли призначати обробники

Обробники можна призначати лише елементам, які вже існують у DOM. У нашому проєкті скрипт підключено з `defer` — він виконується після розбору всього HTML, тому `document.getElementById(...)` гарантовано знаходить елементи. Без `defer` (скрипт у `<head>`) довелося б чекати на подію `DOMContentLoaded`:

```js
document.addEventListener('DOMContentLoaded', () => {
  // тут DOM уже побудовано
});
```

## 3. Об'єкт події

Браузер передає в обробник першим аргументом **об'єкт події** (event object) з інформацією про те, що сталося.

```js
document.addEventListener('click', (event) => {
  console.log(event.type);           // 'click'
  console.log(event.target);         // елемент, по якому реально клацнули
  console.log(event.currentTarget);  // елемент, на якому висить обробник (тут document)
  console.log(event.clientX, event.clientY); // координати відносно вікна
  console.log(event.timeStamp);      // час події (мс від завантаження сторінки)
  console.log(event.isTrusted);      // true — подію створив користувач, а не скрипт
});
```

### `target` і `currentTarget`

Це найважливіша пара властивостей:

- `event.target` — **найглибший** елемент, де сталася подія (наприклад, `<span>` усередині кнопки).
- `event.currentTarget` — елемент, **чий обробник зараз виконується**.

```html
<ul id="menu">
  <li><button>Головна <span class="badge">3</span></button></li>
</ul>
```

```js
document.getElementById('menu').addEventListener('click', (event) => {
  console.log(event.target);        // <span class="badge"> — якщо клікнули по цифрі
  console.log(event.currentTarget); // <ul id="menu">
});
```

### Властивості подій миші та вказівника

| Властивість | Значення |
|---|---|
| `clientX`, `clientY` | координати відносно видимої частини вікна |
| `pageX`, `pageY` | координати відносно всього документа (з урахуванням прокручування) |
| `offsetX`, `offsetY` | координати відносно елемента-цілі |
| `button` | яка кнопка: 0 — ліва, 1 — середня, 2 — права |
| `altKey`, `ctrlKey`, `shiftKey`, `metaKey` | чи затиснута клавіша-модифікатор |
| `pointerType` (для `pointer*`) | `'mouse'`, `'pen'`, `'touch'` |

### Властивості подій клавіатури

| Властивість | Приклад для клавіші «Ф» в українській розкладці | Призначення |
|---|---|---|
| `key` | `'ф'` (або `'Ф'` із Shift) | **символ**, що вводиться; для службових: `'Enter'`, `'Escape'`, `'ArrowUp'` |
| `code` | `'KeyA'` | **фізична клавіша**, не залежить від розкладки |
| `repeat` | `true`, якщо клавішу утримують | автоповтор |

```js
document.addEventListener('keydown', (event) => {
  if (event.key === 'Escape') {
    closeModal();
  }
  // Ctrl+S / Cmd+S незалежно від розкладки
  if ((event.ctrlKey || event.metaKey) && event.code === 'KeyS') {
    event.preventDefault(); // не відкривати діалог «Зберегти сторінку»
    saveData();
  }
});
```

Використовуйте `key` для перевірки службових клавіш і введених символів, `code` — для гарячих клавіш, які мають працювати в будь-якій розкладці. Застарілі властивості `keyCode` і `which` не використовуйте.

### `this` в обробнику

У звичайній функції-обробнику `this` дорівнює `event.currentTarget`. У стрілковій функції `this` береться із зовнішнього контексту і на елемент **не вказує**.

```js
button.addEventListener('click', function () {
  this.classList.toggle('active'); // this === button
});

button.addEventListener('click', () => {
  // this тут — не кнопка! Використовуйте event.currentTarget
});
```

Щоб не плутатися, у сучасному коді зазвичай пишуть стрілкові функції й беруть елемент з `event.currentTarget` або `event.target`.

## 4. Поширення подій: занурення і спливання

Коли ви клацаєте по `<span>` усередині `<button>` усередині `<li>`, подія стосується не лише `<span>`, а й усіх його предків: кнопки, пункту списку, списку, `body`, `html`, `document`, `window`. Подія проходить через усі ці елементи у **три фази**:

```text
                window
                  │  ▲
                document
                  │  │
     1. Занурення  html   3. Спливання
     (capturing)   │  │   (bubbling)
                  body
                  │  │
                  ul
                  │  │
                  li
                  ▼  │
             2. Ціль: span (target)
```

1. **Фаза занурення** (capturing phase) — від `window` вниз до цілі.
2. **Фаза цілі** (target phase) — подія досягла `event.target`.
3. **Фаза спливання** (bubbling phase) — від цілі вгору до `window`.

За замовчуванням `addEventListener` реєструє обробник у фазі **спливання**. Щоб обробляти в фазі занурення, передають `{ capture: true }` (або просто `true` третім аргументом).

```js
for (const el of document.querySelectorAll('ul, li, button')) {
  el.addEventListener('click', () => console.log('спливання:', el.tagName));
  el.addEventListener('click', () => console.log('занурення:', el.tagName), { capture: true });
}
// Клік по кнопці:
// занурення: UL → занурення: LI → занурення: BUTTON (ціль)
// спливання: BUTTON → спливання: LI → спливання: UL
```

### Зупинка поширення

```js
button.addEventListener('click', (event) => {
  event.stopPropagation(); // далі вгору подія не піде
});
```

- `stopPropagation()` — зупиняє поширення до наступних елементів, але інші обробники на **цьому** елементі виконаються.
- `stopImmediatePropagation()` — зупиняє й обробники на поточному елементі.

:::caution[Не зловживайте stopPropagation]
Зупинка спливання ламає код, що покладається на нього: делегування, аналітику, закриття випадних меню кліком поза ними. Майже завжди замість `stopPropagation` краще в батьківському обробнику перевірити, по чому саме клікнули (`event.target.closest(...)`).
:::

### Події, які не спливають

Більшість подій спливає, але є винятки: `focus`, `blur`, `mouseenter`, `mouseleave`, `load` (на зображеннях), `scroll` (на елементах). Для фокуса є спливаючі аналоги `focusin` і `focusout`, для миші — `mouseover` / `mouseout`. Перевірити можна властивістю `event.bubbles`.

## 5. Делегування подій

Уявімо список витрат, де в кожному пункті є кнопка «Видалити». Наївний підхід — призначити обробник кожній кнопці:

```js
// Наївний підхід — НЕ рекомендується
for (const button of document.querySelectorAll('.delete')) {
  button.addEventListener('click', () => { /* видалити */ });
}
```

Проблеми:

- кнопки нових пунктів, доданих пізніше, обробника **не матимуть**;
- після кожного перемальовування списку обробники доведеться вішати знову;
- 1000 пунктів — 1000 функцій-обробників у пам'яті.

**Делегування подій** (event delegation) використовує спливання: один обробник ставлять на **спільного предка** (сам список), а в ньому визначають, по якому саме елементу клікнули.

```html
<ul id="list">
  <li class="expense" data-id="1">Кава <button class="delete">✕</button></li>
  <li class="expense" data-id="2">Таксі <button class="delete">✕</button></li>
</ul>
```

```js
const list = document.getElementById('list');

list.addEventListener('click', (event) => {
  const button = event.target.closest('button.delete');
  if (!button) return;               // клік не по кнопці видалення

  const item = button.closest('li.expense');
  const id = Number(item.dataset.id); // data-id — завжди рядок!
  console.log('Видалити витрату', id);
});
```

Ключові інструменти делегування:

| Метод / властивість | Що робить |
|---|---|
| `el.closest(selector)` | повертає найближчого предка (або сам елемент), що відповідає селектору, або `null` |
| `el.matches(selector)` | перевіряє, чи відповідає елемент селектору (`true`/`false`) |
| `el.dataset` | об'єкт з атрибутами `data-*`: `data-id` → `dataset.id`, `data-sort-key` → `dataset.sortKey` |
| `list.contains(el)` | чи знаходиться `el` всередині `list` |

:::tip[Чому closest, а не перевірка target]
Перевірка `event.target.classList.contains('delete')` зламається, якщо в кнопці є іконка `<svg>` чи `<span>`: тоді `target` — це іконка. `closest` піднімається від `target` вгору і знаходить кнопку незалежно від її вмісту.
:::

Переваги делегування: один обробник замість багатьох, автоматично працює для нових елементів, не треба нічого перепризначати після перемальовування. Делегування — стандартний прийом для списків, таблиць, меню, панелей з кнопками.

## 6. Дії за замовчуванням і події форм

Багато подій мають **дію за замовчуванням** (default action), яку браузер виконує після обробників:

| Подія | Дія за замовчуванням |
|---|---|
| `click` на `<a href>` | перехід за посиланням |
| `submit` форми | відправлення даних і перезавантаження сторінки |
| `click` на чекбоксі | зміна стану `checked` |
| `keydown` в полі | введення символу |
| `contextmenu` | показ контекстного меню |
| `wheel`, `touchmove` | прокручування |

Метод `event.preventDefault()` скасовує цю дію. Перевірити, чи її скасовано, можна через `event.defaultPrevented`.

### Обробка форми

```html
<form id="login-form" novalidate>
  <input name="email" type="email" required>
  <input name="password" type="password" minlength="8" required>
  <button type="submit">Увійти</button>
</form>
```

```js
const form = document.getElementById('login-form');

form.addEventListener('submit', (event) => {
  event.preventDefault(); // без цього сторінка перезавантажиться

  const data = new FormData(form);
  const email = data.get('email').trim();
  const password = data.get('password');

  if (!email.includes('@')) {
    form.elements.email.classList.add('invalid');
    return;
  }
  console.log('Відправляємо', { email, password });
  form.reset(); // очищення полів
});
```

:::caution[Слухайте submit, а не click по кнопці]
Форму можна відправити не лише кліком по кнопці, а й клавішею Enter у текстовому полі. Подія `submit` на формі спрацює в обох випадках, а `click` на кнопці — ні. Крім того, кнопка без явного `type` усередині форми має тип `submit` за замовчуванням: «звичайні» кнопки у формі позначайте `type="button"`.
:::

### Події полів введення

| Подія | Коли спрацьовує | Типове застосування |
|---|---|---|
| `input` | при **кожній** зміні значення (кожен символ, вставка, вибір) | живий пошук, лічильник символів, скидання помилки |
| `change` | коли зміну **зафіксовано**: для тексту — після втрати фокуса, для `select`/`checkbox`/`date` — одразу після вибору | фільтри, перемикачі |
| `focus` / `blur` | поле отримало / втратило фокус (не спливають) | підказки, валідація при виході з поля |
| `focusin` / `focusout` | те саме, але спливають | делегування на рівні форми |
| `submit` | відправлення форми | обробка введених даних |
| `reset` | очищення форми | скидання стану |

### Вбудована валідація і `novalidate`

Атрибути `required`, `min`, `max`, `minlength`, `pattern`, `type="email"` вмикають **вбудовану валідацію** браузера: при помилці подія `submit` навіть не настає, а браузер показує свою спливну підказку. Це зручно, але вигляд підказок не налаштовується і мова залежить від браузера.

Якщо ми хочемо показувати власні повідомлення, на форму додають атрибут `novalidate` і перевіряють дані в обробнику `submit`. Атрибути `required`, `min` тощо при цьому можна залишити: вони корисні для доступності і їх можна перевірити з JS через Constraint Validation API (`input.validity.valueMissing`, `input.checkValidity()`).

### Значення полів: завжди рядки

```js
amountInput.value;           // '250' — рядок, навіть для type="number"
Number(amountInput.value);   // 250
Number('');                  // 0  — порожнє поле стає нулем!
amountInput.valueAsNumber;   // 250 або NaN для порожнього поля
dateInput.value;             // '2026-02-03' або '' — формат завжди YYYY-MM-DD
select.value;                // value вибраного <option>
checkbox.checked;            // true / false
```

## 7. Огляд основних типів подій

| Група | Події | Примітки |
|---|---|---|
| Миша | `click`, `dblclick`, `contextmenu`, `mousedown`, `mouseup`, `mousemove`, `mouseover`/`mouseout`, `mouseenter`/`mouseleave` | `click` спрацьовує і з клавіатури (Enter/Space на кнопці) |
| Вказівник | `pointerdown`, `pointerup`, `pointermove`, `pointercancel` | єдина модель для миші, пера і дотику — краще за окремі `touch*` |
| Клавіатура | `keydown`, `keyup` | `keypress` застаріла |
| Форми | `input`, `change`, `submit`, `reset`, `focus`, `blur`, `focusin`, `focusout`, `invalid` | |
| Документ і вікно | `DOMContentLoaded`, `load`, `beforeunload`, `visibilitychange`, `resize`, `scroll` | `beforeunload` — попередження про незбережені дані |
| Буфер обміну | `copy`, `cut`, `paste` | `event.clipboardData` |
| Перетягування | `dragstart`, `dragover`, `drop` | HTML Drag and Drop API |
| Анімації | `transitionend`, `animationend` | завершення CSS-переходу або анімації |
| Мережа | `online`, `offline` | на `window` |

### Часті події: debounce і throttle

Події `input`, `scroll`, `resize`, `mousemove` можуть спрацьовувати десятки разів на секунду. Якщо в обробнику важка робота (запит на сервер, перемальовування великого списку), застосовують:

- **debounce** («відкладення») — виконати функцію лише тоді, коли події припинилися на N мс (живий пошук: запит після паузи у введенні);
- **throttle** («обмеження частоти») — виконувати не частіше ніж раз на N мс (оновлення позиції при прокручуванні).

```js
function debounce(fn, ms) {
  let timerId;
  return (...args) => {
    clearTimeout(timerId);
    timerId = setTimeout(() => fn(...args), ms);
  };
}

searchInput.addEventListener('input', debounce((event) => {
  console.log('Шукаємо:', event.target.value);
}, 300));
```

### Власні події

Можна створювати й запускати свої події — це зручний спосіб «повідомити» інші частини коду про зміну стану:

```js
document.addEventListener('expense:added', (event) => {
  console.log('Додано витрату', event.detail);
});

document.dispatchEvent(new CustomEvent('expense:added', {
  detail: { title: 'Кава', amount: 60 },
}));
```

## 8. Маніпуляції DOM для інтерактивних інтерфейсів

На практичній 7 ми знайомилися з пошуком елементів і створенням вузлів. Для інтерактивності знадобляться ще кілька інструментів. Нагадаємо, що DOM (Document Object Model) — це дерево об'єктів, яке браузер будує з HTML; кожен тег стає вузлом-елементом, текст — текстовим вузлом.

### Навігація деревом

| Властивість / метод | Що повертає |
|---|---|
| `el.parentElement` | батьківський елемент |
| `el.children` | живу колекцію дочірніх **елементів** (без текстових вузлів) |
| `el.firstElementChild`, `el.lastElementChild` | перший / останній дочірній елемент |
| `el.previousElementSibling`, `el.nextElementSibling` | сусідні елементи |
| `el.closest(sel)` | найближчий предок за селектором |
| `el.querySelector(sel)`, `el.querySelectorAll(sel)` | пошук **всередині** елемента |

### Вставка, заміна, видалення

```js
const li = document.createElement('li');
li.textContent = 'Новий пункт';

list.append(li);             // у кінець (можна кілька вузлів і рядків)
list.prepend(li);            // на початок
list.firstElementChild.before(li); // перед елементом
list.lastElementChild.after(li);   // після елемента
oldItem.replaceWith(li);     // замінити елемент
li.remove();                 // видалити елемент
list.replaceChildren();      // очистити список
list.replaceChildren(a, b);  // замінити весь вміст новими вузлами
```

### Два підходи до оновлення інтерфейсу

1. **Точкові зміни**: додали витрату — `list.append(newItem)`; видалили — `item.remove()`; оновили суму — змінили один `textContent`. Швидко, але легко отримати розбіжність між даними і тим, що на екрані.
2. **Перемальовування зі стану** (render from state): дані зберігаються в масиві; будь-яка дія змінює масив і викликає одну функцію `render()`, яка заново будує список, суму і статистику з масиву.

```text
  Подія (submit, click, change)
           │
           ▼
  Зміна даних (масив expenses, фільтр, сортування)
           │
           ▼
  render() ──► renderList() + renderTotal() + renderStats()
           │
           ▼
  DOM завжди відповідає даним
```

Другий підхід простіший і надійніший: інтерфейс **завжди** є функцією від даних. Для десятків і сотень елементів він достатньо швидкий. Саме так працюють React, Vue та інші фреймворки — тільки вони ще й розумно оновлюють лише ті вузли, що змінилися. У «Трекері витрат» ми використаємо саме цей підхід.

### Класи, атрибути і стилі як відгук на події

```js
input.classList.add('invalid');
input.classList.remove('invalid');
input.classList.toggle('invalid', hasError); // другий аргумент: true — додати, false — прибрати
button.setAttribute('aria-pressed', 'true');
button.disabled = true;
bar.style.width = `${percent}%`;
```

Перевага `classList.toggle(name, condition)` — один рядок замість `if/else`. Для зовнішнього вигляду змінюйте **класи**, а не `style`: стилі мають жити в CSS.

## 9. Типові помилки та доступність

### Типові помилки

| Помилка | Наслідок | Як правильно |
|---|---|---|
| `button.addEventListener('click', handle())` | функція викликається **одразу**, а обробником стає її результат (`undefined`) | передавати посилання: `handle` або `() => handle(id)` |
| Обробник на `click` кнопки форми замість `submit` форми | Enter у полі не обробляється, сторінка перезавантажується | `form.addEventListener('submit', ...)` + `preventDefault()` |
| Забутий `preventDefault()` у `submit` | сторінка перезавантажується, дані губляться | викликати першим рядком обробника |
| Обробники кнопкам, які потім перемальовуються | після `render()` кнопки «мертві» | делегування на постійному батьківському елементі |
| Порівняння `dataset.id === 3` | завжди `false`, бо `dataset` містить рядки | `Number(el.dataset.id) === 3` |
| Повторне призначення обробника в функції, що викликається багато разів | обробник спрацьовує 2, 3, 10 разів за один клік | призначати обробники **один раз** при ініціалізації |
| Кнопка без `type` у формі | будь-яка кнопка відправляє форму | `type="button"` для звичайних кнопок |

### Доступність (accessibility)

- Для дій використовуйте **`<button>`**, а не `<div onclick>`. Кнопка отримує фокус клавішею Tab, натискається Enter і Space, зчитується програмами екранного доступу як кнопка. `div` нічого з цього не вміє.
- Кнопкам з іконкою замість тексту (наприклад, «✕») додавайте `aria-label="Видалити «Кава»"`.
- Для кнопок-перемикачів (сортування, тема) використовуйте `aria-pressed="true|false"`.
- Повідомлення про помилки і статуси розміщуйте в елементі з `role="status"` або `aria-live="polite"` — програма екранного доступу зачитає зміну тексту.
- Поле з помилкою позначайте `aria-invalid="true"` і переводьте на нього фокус, щоб користувач клавіатури одразу потрапив до проблеми.

## Підсумки

- Браузер працює за подієвою моделлю: обробники викликаються циклом подій, коли поточний код завершився; довгі обробники блокують інтерфейс.
- Основний спосіб призначення обробників — `addEventListener(type, handler, options)`; видалення — `removeEventListener` з тією самою функцією або через `AbortController` і `signal`.
- Об'єкт події містить `type`, `target` (де сталося), `currentTarget` (чий обробник), координати, клавіші-модифікатори, `key`/`code` для клавіатури.
- Подія проходить фази занурення, цілі та спливання; за замовчуванням обробники працюють на спливанні.
- Делегування — один обробник на батьківському елементі + `event.target.closest(selector)` — основа роботи з динамічними списками.
- `preventDefault()` скасовує дію за замовчуванням; форми обробляємо через `submit` на формі, з власною валідацією і `novalidate`.
- Надійна схема інтерактивного застосунку: подія → зміна даних → `render()` перемальовує інтерфейс зі стану.
