## 1. Навіщо потрібні функції

**Функція** — іменований блок коду, який приймає вхідні дані (параметри), виконує дію і, можливо, повертає результат. Функції дозволяють:

- **не повторювати код** (принцип DRY — *Don't Repeat Yourself*);
- **давати назви** діям: `format_price($sum)` читається краще за `number_format($sum, 2, ',', ' ') . ' грн'`;
- **ізолювати** логіку: змінні всередині функції не заважають зовнішньому коду;
- **тестувати** частини програми окремо.

### Оголошення і виклик

```php
<?php
declare(strict_types=1);

function greet(string $name): string
{
    return "Привіт, {$name}!";
}

echo greet('Оксана'); // Привіт, Оксана!
```

Складові:

| Частина | У прикладі | Пояснення |
|---|---|---|
| Ключове слово | `function` | |
| Ім'я | `greet` | `snake_case` або `camelCase`, дієслово, не чутливе до регістру |
| Параметри | `string $name` | тип (необов'язково, але бажано) + ім'я |
| Тип повернення | `: string` | після дужок |
| Тіло | `{ ... }` | |
| `return` | `return "...";` | завершує функцію і повертає значення |

Функції, оголошені на верхньому рівні файлу, можна викликати **до** їх оголошення в тому самому файлі (PHP «бачить» їх під час компіляції). Але функцію, оголошену всередині `if` або в іншому файлі, можна викликати лише після того, як цей код виконано (файл підключено).

Функцію з тим самим ім'ям не можна оголосити двічі — буде `Fatal error: Cannot redeclare greet()`. Це часто трапляється, коли файл з функціями підключають двічі — рішення в розділі 9.

## 2. Типи параметрів і повернення

### Доступні типи

| Тип | Приклад |
|---|---|
| Скалярні | `int`, `float`, `string`, `bool` |
| `array`, `iterable`, `callable`, `object` | `function sum(array $numbers): int` |
| Ім'я класу | `function format(DateTime $date): string` |
| Nullable | `?string` — рядок або `null` |
| Union (PHP 8.0) | `int\|float`, `string\|null` |
| `mixed` | будь-яке значення (уникайте без потреби) |
| `void` | функція нічого не повертає |
| `never` (PHP 8.1) | функція ніколи не повертає керування (`exit` або виняток) |
| `true`, `false`, `null` (PHP 8.2) | як окремі типи, напр. `array\|false` |

```php
<?php
declare(strict_types=1);

function average(array $numbers): ?float
{
    if ($numbers === []) {
        return null;                         // для порожнього масиву середнього немає
    }
    return array_sum($numbers) / count($numbers);
}

function percent(int|float $part, int|float $total): float
{
    return $total == 0 ? 0.0 : $part / $total * 100;
}

function log_message(string $message): void
{
    error_log('[' . date('H:i:s') . '] ' . $message);
    // return; без значення — можна, return 1; — помилка
}

function abort(int $code, string $message): never
{
    http_response_code($code);
    echo $message;
    exit;                                    // функція з never мусить завершити скрипт або кинути виняток
}
```

### Як працюють типи без і з `strict_types`

```php
function double(int $n): int
{
    return $n * 2;
}

// Без declare(strict_types=1) — «режим примусу» (coercive):
double('21');    // 42 — рядок перетворено на int
double(21.0);    // 42 — float без дробової частини перетворено
double(21.5);    // 42 + Deprecated: втрата точності
double('abc');   // TypeError

// З declare(strict_types=1) у файлі, де відбувається ВИКЛИК:
double('21');    // TypeError: Argument #1 ($n) must be of type int, string given
double(21);      // 42 — дозволено лише int (виняток: int можна передати туди, де очікують float)
```

Важливо: `strict_types` діє на виклики **у тому файлі, де стоїть директива**, а не там, де оголошено функцію.

:::tip[Чому типи — це добре]
Типи — це документація, яку перевіряє машина. Intelephense підсвічує помилку ще до запуску, а PHP падає з чітким повідомленням `TypeError` замість того, щоб мовчки повернути дивний результат, який ви знайдете за тиждень. Ми типізуємо всі параметри і повернення в нашому коді.
:::

### Дані з форм — завжди рядки

Уже на П6 ви побачите: усе, що надходить від користувача через `$_GET` і `$_POST`, — це **рядки** (або масиви рядків). Навіть `?page=2` дає `'2'`, а не `2`. Тому перед передачею в типізовану функцію значення треба перевірити і перетворити:

```php
$page = filter_var($_GET['page'] ?? 1, FILTER_VALIDATE_INT, ['options' => ['min_range' => 1]]);
if ($page === false) {
    $page = 1;
}
show_page($page); // тепер це гарантовано int ≥ 1
```

## 3. Параметри

### Значення за замовчуванням

```php
function excerpt(string $text, int $length = 100, string $suffix = '…'): string
{
    if (mb_strlen($text) <= $length) {
        return $text;
    }
    return rtrim(mb_substr($text, 0, $length)) . $suffix;
}

excerpt($body);              // 100 символів і «…»
excerpt($body, 50);          // 50 символів
excerpt($body, 50, '...');   // інший суфікс
```

Параметри зі значеннями за замовчуванням ставлять **після** обов'язкових. Значення за замовчуванням має бути константним виразом (число, рядок, масив, `null`, константа, `new` об'єкта з PHP 8.1), а не викликом функції.

### Іменовані аргументи (PHP 8.0)

Аргументи можна передавати за **іменем параметра** — у будь-якому порядку і пропускаючи необов'язкові:

```php
excerpt($body, suffix: ' [далі]');            // length лишається 100

htmlspecialchars($text, double_encode: false); // не треба перелічувати flags і encoding

number_format(num: 1234.5, decimals: 2, decimal_separator: ',', thousands_separator: ' ');
```

Переваги: код самодокументується, не треба пам'ятати порядок і писати значення за замовчуванням для проміжних параметрів. Але ім'я параметра стає частиною «контракту» функції — перейменування параметра ламає виклики з іменованими аргументами.

### Variadic-параметри і розпакування

Параметр з `...` збирає всі «зайві» аргументи в масив:

```php
function sum_all(int|float ...$numbers): int|float
{
    return array_sum($numbers);
}

sum_all(1, 2, 3);      // 6
sum_all();             // 0

$values = [10, 20, 30];
sum_all(...$values);   // 60 — оператор розпакування (spread) перетворює масив на аргументи

function tag(string $name, string ...$classes): string
{
    $class = implode(' ', $classes);
    return "<{$name} class=\"{$class}\">";
}

tag('div', 'card', 'card--active'); // <div class="card card--active">
```

## 4. Передача за значенням і за посиланням

За замовчуванням параметри передаються **за значенням**: функція отримує копію, і зміни всередині не впливають на зовнішню змінну. Це стосується й масивів.

```php
function add_tag(array $tags, string $tag): array
{
    $tags[] = $tag;    // змінюємо копію
    return $tags;      // і повертаємо нову версію
}

$tags = ['php'];
$newTags = add_tag($tags, 'web');
// $tags    — ['php']
// $newTags — ['php', 'web']
```

Щоб функція могла змінити зовнішню змінну, параметр позначають `&`:

```php
function add_tag_in_place(array &$tags, string $tag): void
{
    $tags[] = $tag;    // змінюємо оригінал
}

$tags = ['php'];
add_tag_in_place($tags, 'web');
// $tags — ['php', 'web']
```

Вбудовані функції теж бувають «за посиланням»: `sort(array &$array)`, `array_push(array &$array, ...)`, `preg_match($pattern, $subject, &$matches)`.

| | За значенням | За посиланням |
|---|---|---|
| Синтаксис | `array $tags` | `array &$tags` |
| Зміни всередині | не видно ззовні | змінюють оригінал |
| Передбачуваність | висока | низька (побічні ефекти) |
| Коли використовувати | майже завжди | рідко, коли повернути результат незручно |

:::tip[Чисті функції]
Функція, яка залежить лише від своїх параметрів і не має побічних ефектів (не змінює зовнішні змінні, не пише у файли, не виводить), називається **чистою (pure)**. Її легко тестувати і повторно використовувати. Намагайтеся, щоб більшість хелперів були чистими, а «брудні» дії (читання файлу, `echo`, `header()`) були зібрані в небагатьох місцях.
:::

## 5. Області видимості

Тут PHP суттєво відрізняється від JavaScript: **функція не бачить змінних, оголошених поза нею**.

```php
$siteName = 'Міні-блог';

function show_title(): void
{
    echo $siteName; // Warning: Undefined variable $siteName
}
```

У JavaScript функція «замикала» б зовнішню змінну автоматично. У PHP кожна іменована функція має **власну локальну область видимості**, і в ній доступні лише параметри, локальні змінні та суперглобальні масиви (`$_GET`, `$_POST`, `$_SERVER`, `$_SESSION`…).

### Ключове слово `global` (не рекомендується)

```php
function show_title(): void
{
    global $siteName;      // підключити глобальну змінну
    echo $siteName;
}
```

Працює, але створює приховані залежності: функція раптом залежить від того, що хтось десь оголосив змінну з певним ім'ям. Правильно — **передати значення параметром** або оголосити **константу** (константи видно звідусіль):

```php
const SITE_NAME = 'Міні-блог';

function show_title(): void
{
    echo SITE_NAME;        // константи доступні в будь-якій функції
}
```

### Статичні змінні

Змінна з `static` зберігає значення між викликами функції (у межах одного запиту):

```php
function next_id(): int
{
    static $id = 0;    // ініціалізується лише один раз
    return ++$id;
}

echo next_id(); // 1
echo next_id(); // 2
echo next_id(); // 3
```

Типове застосування — кешування дорогого результату (наприклад, з'єднання з базою даних чи прочитаного файлу) в межах запиту. Пам'ятайте: після завершення запиту значення зникне (share-nothing).

## 6. Анонімні і стрілкові функції

### Анонімна функція (closure)

Функція без імені, яку можна присвоїти змінній або передати як аргумент:

```php
$square = function (int $n): int {
    return $n * $n;
};               // крапка з комою — це присвоєння

echo $square(5); // 25
```

Анонімна функція теж **не бачить** зовнішніх змінних. Щоб «захопити» їх, використовують `use`:

```php
$vat = 0.2;

$withVat = function (float $price) use ($vat): float {
    return $price * (1 + $vat);
};

echo $withVat(100); // 120

$vat = 0.5;
echo $withVat(100); // 120 — значення захоплено в момент створення (за значенням)
```

Захоплення за посиланням — `use (&$counter)`: тоді функція бачить і змінює актуальне значення.

### Стрілкові функції `fn` (PHP 7.4)

Короткий синтаксис для однорядкових функцій. Стрілкова функція **автоматично** захоплює зовнішні змінні (за значенням) і неявно повертає результат виразу:

```php
$vat = 0.2;
$withVat = fn(float $price): float => $price * (1 + $vat);

$numbers = [1, 2, 3, 4];
$squares = array_map(fn(int $n): int => $n ** 2, $numbers); // [1, 4, 9, 16]
```

| | `function () use (...) { }` | `fn() => ...` |
|---|---|---|
| Тіло | будь-яка кількість інструкцій | **один вираз** |
| `return` | явний | неявний |
| Захоплення змінних | явно через `use` | автоматично, за значенням |
| Змінити зовнішню змінну | так, через `use (&$x)` | ні |

Порівняння з JavaScript: `fn($x) => $x * 2` — майже те саме, що `x => x * 2`, але зі знаком `$`, словом `fn` і без фігурних дужок для багаторядкового тіла.

### Функція як значення: `callable`

Функцію можна передати в іншу функцію кількома способами:

```php
array_map('strtoupper', ['a', 'b']);       // ім'я функції рядком
array_map(strtoupper(...), ['a', 'b']);     // first-class callable syntax (PHP 8.1) — краще: перевіряється Intelephense
array_map(fn($s) => strtoupper($s), $list); // стрілкова функція

function apply_twice(callable $fn, int $value): int
{
    return $fn($fn($value));
}

echo apply_twice(fn(int $x): int => $x + 10, 1); // 21
```

## 7. Функції вищого порядку для масивів

**Функція вищого порядку** — функція, що приймає або повертає іншу функцію. Для масивів ключові такі:

### `array_map` — перетворити кожен елемент

```php
$posts = [
    ['id' => 1, 'title' => 'вступ до php', 'views' => 120],
    ['id' => 2, 'title' => 'масиви',       'views' => 75],
    ['id' => 3, 'title' => 'функції',      'views' => 210],
];

$titles = array_map(
    fn(array $post): string => mb_convert_case($post['title'], MB_CASE_TITLE),
    $posts
);
// ['Вступ До Php', 'Масиви', 'Функції']
```

Зверніть увагу на порядок аргументів: у `array_map` спочатку **функція**, потім масив.

### `array_filter` — відібрати елементи

```php
$popular = array_filter($posts, fn(array $post): bool => $post['views'] >= 100);
// ключі зберігаються: [0 => ..., 2 => ...]

$popular = array_values($popular); // перенумерувати: [0 => ..., 1 => ...]

// Без функції — видаляє всі falsy-значення
array_filter(['php', '', 'js', null, '0']); // [0 => 'php', 2 => 'js'] — увага, '0' теж видалено!
```

У `array_filter` порядок навпаки: спочатку **масив**, потім функція. Ця непослідовність — історична особливість PHP, яку просто треба запам'ятати (Intelephense підкаже).

:::caution[Ключі після array_filter]
`array_filter` зберігає вихідні ключі. Якщо далі ви звертаєтесь до `$result[0]` або перетворюєте масив на JSON (`json_encode`), «дірки» в ключах дадуть несподіваний результат — JSON-об'єкт замість масиву. Використовуйте `array_values()`, щоб перенумерувати.
:::

### `array_reduce` — згорнути до одного значення

```php
$totalViews = array_reduce(
    $posts,
    fn(int $carry, array $post): int => $carry + $post['views'],
    0                                    // початкове значення акумулятора
);
// 405
```

### `usort` — сортування з функцією порівняння

Функція порівняння отримує два елементи і повертає від'ємне число, 0 або додатне. Оператор `<=>` робить саме це:

```php
// за переглядами, за спаданням (b <=> a)
usort($posts, fn(array $a, array $b): int => $b['views'] <=> $a['views']);

// за назвою, за зростанням
usort($posts, fn(array $a, array $b): int => strcmp($a['title'], $b['title']));

// за кількома критеріями: спочатку за views (спадання), потім за id (зростання)
usort($posts, fn(array $a, array $b): int =>
    [$b['views'], $a['id']] <=> [$a['views'], $b['id']]
);
```

Як і `sort`, функція `usort` змінює масив на місці (параметр за посиланням) і повертає `true`.

### Порівняння з JavaScript

| JavaScript | PHP |
|---|---|
| `arr.map(fn)` | `array_map($fn, $arr)` |
| `arr.filter(fn)` | `array_filter($arr, $fn)` + `array_values()` |
| `arr.reduce(fn, init)` | `array_reduce($arr, $fn, $init)` |
| `arr.sort((a, b) => a - b)` | `usort($arr, fn($a, $b) => $a <=> $b)` |
| `arr.find(fn)` | `array_find($arr, $fn)` (PHP 8.4) або цикл `foreach` з `return` |
| `arr.some(fn)` / `arr.every(fn)` | `array_any` / `array_all` (PHP 8.4) або цикл |
| `arr.includes(x)` | `in_array($x, $arr, true)` |
| `arr.join(', ')` | `implode(', ', $arr)` |

Оскільки в курсі мінімальна версія PHP — 8.2, замість `array_find` пишемо власну функцію:

```php
function find_post(array $posts, int $id): ?array
{
    foreach ($posts as $post) {
        if ($post['id'] === $id) {
            return $post;   // ранній вихід — знайшли
        }
    }
    return null;            // не знайшли
}
```

## 8. Рекурсія

**Рекурсивна** функція викликає сама себе. Вона обов'язково має **базовий випадок** (умову зупинки), інакше нескінченні виклики вичерпають стек.

```php
function factorial(int $n): int
{
    if ($n <= 1) {
        return 1;                    // базовий випадок
    }
    return $n * factorial($n - 1);   // рекурсивний виклик
}
```

Практичний приклад — обхід вкладеної структури (дерево меню, категорій, коментарів з відповідями):

```php
$menu = [
    ['title' => 'Головна'],
    ['title' => 'Курси', 'children' => [
        ['title' => 'PHP'],
        ['title' => 'JavaScript', 'children' => [
            ['title' => 'React'],
        ]],
    ]],
];

function render_menu(array $items): string
{
    $html = '<ul>';
    foreach ($items as $item) {
        $html .= '<li>' . htmlspecialchars($item['title']);
        if (!empty($item['children'])) {
            $html .= render_menu($item['children']); // рекурсія для підменю
        }
        $html .= '</li>';
    }
    return $html . '</ul>';
}

echo render_menu($menu);
```

## 9. Організація коду: `require` та `include`

Коли функцій стає багато, їх виносять в окремий файл і підключають там, де потрібно. PHP має чотири конструкції:

| Конструкція | Якщо файлу немає | Повторне підключення |
|---|---|---|
| `include 'file.php'` | Warning, скрипт **продовжує** роботу | підключає ще раз |
| `require 'file.php'` | Fatal error, скрипт **зупиняється** | підключає ще раз |
| `include_once 'file.php'` | Warning | пропускає, якщо вже підключено |
| `require_once 'file.php'` | Fatal error | пропускає, якщо вже підключено |

Рекомендації:

- для файлів, без яких програма не може працювати (функції, конфігурація, з'єднання з БД), використовуйте **`require`** (або `require_once`, якщо файл може підключатися з кількох місць);
- для шаблонних фрагментів (шапка, підвал сторінки) теж зазвичай `require`: сторінка без шапки — це помилка, яку краще побачити одразу;
- завжди будуйте шлях від **`__DIR__`**:

```php
require __DIR__ . '/includes/helpers.php';
```

Відносний шлях `'includes/helpers.php'` PHP шукає відносно **поточної робочої папки** і `include_path`, а не відносно файлу, в якому написано `require`. Коли один файл підключає інший, який підключає третій, відносні шляхи легко «ламаються». `__DIR__` завжди вказує на папку файлу, де записано вираз.

### Підключений файл бачить змінні

`require` фактично «вставляє» код файлу в місце підключення. Підключений файл бачить змінні з області видимості, де стоїть `require`, — цим користуються для шаблонів:

```php title="page.php"
<?php
$pageTitle = 'Про нас';
require __DIR__ . '/includes/header.php'; // header.php виведе <title><?= $pageTitle ?></title>
```

### Файл хелперів

Поширена практика — файл `helpers.php` з невеликими універсальними функціями:

```php title="includes/helpers.php"
<?php
declare(strict_types=1);

/**
 * Екранує рядок для безпечного виведення в HTML.
 */
function e(?string $value): string
{
    return htmlspecialchars($value ?? '', ENT_QUOTES | ENT_SUBSTITUTE, 'UTF-8');
}

/**
 * Форматує ціну: 1234.5 → «1 234,50 грн».
 */
function format_price(float $amount): string
{
    return number_format($amount, 2, ',', ' ') . ' грн';
}
```

Функцію `e()` — коротку обгортку над `htmlspecialchars()` — ми створимо на П5 і використовуватимемо в «Міні-блозі» для **кожного** виведення даних у HTML. Чому це критично для безпеки — детально на П7.

Захист від повторного оголошення, якщо файл може бути підключено двічі:

```php
if (!function_exists('e')) {
    function e(?string $value): string { /* ... */ }
}
```

Проте простіше й чистіше — підключати файл через `require_once` або в одному місці.

## 10. Вбудовані функції і документація

PHP має тисячі вбудованих функцій. Знати їх напам'ять не потрібно, але треба вміти шукати. Документація — [php.net/manual/uk](https://www.php.net/manual/uk/) (частково українською) або англійська версія. Швидкий перехід: `php.net/назва_функції`, наприклад `php.net/array_map`.

Як читати сигнатуру в документації:

```text
array_slice(
    array $array,
    int $offset,
    ?int $length = null,
    bool $preserve_keys = false
): array
```

- обов'язкові параметри — `$array`, `$offset`;
- необов'язкові мають значення за замовчуванням;
- `?int` — можна передати `null`;
- `: array` — що повертає функція;
- розділ **Return Values** пояснює особливі випадки (часто `false` при помилці).

:::caution[Функції, що повертають false]
Багато старих функцій повертають `false` замість винятку при помилці: `file_get_contents()`, `strpos()`, `array_search()`, `json_decode()` (повертає `null`). Класична помилка:

```php
if (strpos('php is fun', 'php')) { /* не виконається! strpos повернув 0 */ }
if (strpos('php is fun', 'php') !== false) { /* правильно */ }
if (str_contains('php is fun', 'php')) { /* ще краще (PHP 8) */ }
```
:::

Корисні групи функцій, які знадобляться в модулі:

| Група | Функції |
|---|---|
| Рядки | `trim`, `mb_strlen`, `mb_substr`, `str_contains`, `sprintf`, `nl2br`, `htmlspecialchars` |
| Масиви | `count`, `array_map`, `array_filter`, `usort`, `array_column`, `in_array`, `array_slice` |
| Дата і час | `date`, `time`, `strtotime`, клас `DateTimeImmutable` |
| Файли | `file_get_contents`, `file_put_contents`, `file_exists`, `is_dir`, `mkdir` |
| JSON | `json_encode`, `json_decode` (з `JSON_THROW_ON_ERROR`) |
| Перевірка даних | `filter_var`, `is_numeric`, `ctype_digit`, `preg_match` |
| Безпека | `random_bytes`, `bin2hex`, `hash_equals`, `password_hash`, `password_verify` |

## Підсумки

- Функція оголошується через `function`, має типізовані параметри і тип повернення; `void` — нічого не повертає, `never` — не повертає керування, `?T` — nullable, `A|B` — union.
- `declare(strict_types=1)` забороняє автоматичне приведення типів при викликах у цьому файлі. Дані з форм — завжди рядки, їх треба перевіряти і перетворювати.
- Параметри за замовчуванням ставлять у кінці; іменовані аргументи (`excerpt($s, suffix: '...')`) дозволяють пропускати необов'язкові; `...$args` збирає аргументи, `...$array` розпаковує.
- За замовчуванням параметри (і масиви!) передаються за значенням; `&` — за посиланням, використовувати рідко.
- Іменована функція **не бачить** зовнішніх змінних: передавайте параметри або використовуйте константи; `static` зберігає значення між викликами в межах запиту.
- Анонімні функції захоплюють змінні через `use`, стрілкові `fn` — автоматично; функції вищого порядку: `array_map`, `array_filter` (+ `array_values`), `array_reduce`, `usort` з `<=>`.
- Код організовуємо в файли: `require __DIR__ . '/includes/helpers.php'`; `require` для обов'язкових файлів, `_once` — від повторного підключення.

## Контрольні питання

1. Які переваги дає типізація параметрів і повернення? Що станеться при виклику `double('21')` з `strict_types=1` і без нього?
2. Чим тип `void` відрізняється від `never`? Наведіть приклад функції з типом `never`.
3. Що таке іменовані аргументи? Перепишіть виклик `htmlspecialchars($s, ENT_QUOTES, 'UTF-8', false)` з іменованим аргументом для останнього параметра.
4. Що виведе код: `function f(array $a) { $a[] = 1; } $x = []; f($x); echo count($x);`? Як змінити функцію, щоб `$x` змінився?
5. Чому іменована функція не бачить зовнішню змінну `$siteName`? Назвіть два правильні способи передати їй це значення.
6. Чим анонімна функція з `use` відрізняється від стрілкової функції `fn`?
7. Чим відрізняється порядок аргументів у `array_map` і `array_filter`? Навіщо після `array_filter` часто викликають `array_values`?
8. Напишіть виклик `usort`, що сортує масив постів за полем `created_at` від нових до старих.
9. Чим `require` відрізняється від `include`, а `require_once` — від `require`? Чому шлях будують від `__DIR__`?
10. Чому перевірка `if (strpos($s, 'php'))` помилкова? Як записати її правильно?
